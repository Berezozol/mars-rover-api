# Дизайн: первые наброски фронтенда

Статичные макеты в `design/mockups/`, открываются двойным щелчком или через локальный HTTP-сервер (ссылки относительные). Фронтенд работает только на API v2 (`docs/API.md`). Название — **Sol Index** (утверждено; нейтральное, без знаков NASA/JPL; в подвале — оговорка «неофициальный проект»).

## Решения владельца (2026-11-17)

1. Название **Sol Index** утверждено.
2. Марсоход без данных (`max_sol = null`) в UI скрыт: карточки на главной, вкладки и списки марсоходов на всех экранах, быстрый переход. Сейчас скрыты Spirit и Opportunity — появятся после импорта архива. Состояние карточки «Archive import pending» убрано; на главной одна строка-подсказка «More rovers appear when their archives are imported».
3. Открытие марсохода ведёт на его последний сол — браузер снимков на `max_sol`. Туда ведут главная кнопка карточки, вкладки и пункт «Photos» в шапке; хроника — вторичная ссылка.

## Экраны

- `index.html` — главная: быстрый переход «марсоход + сол», карточки марсоходов из `GET /rovers` (только с данными: Perseverance, Curiosity) + подсказка про будущие архивы, полоса «последнее от Perseverance» из `/photos/latest`, блок для разработчиков (v1 → смена хоста, v2).
- `photos.html` — браузер снимков одного марсохода: сол или земная дата, камеры, sample_type, сетка, пагинация, состояния (переключатель «Mockup» сверху: данные / загрузка / пустой сол / 422). Без `sol` открывается последний сол марсохода. Данные: Perseverance sol 2031 (52 снимка, это и есть последний) и `?rover=curiosity` — снимки Curiosity sol 1000 (856, только `full`) вместо последнего сола 5066 (оговорено в полосе «Mockup»).
- `photo.html` — карточка снимка (PhotoDetail 81234, SUPERCAM_RMI): большой кадр, переключатель размера, метаданные, подпись, credit, источник, «новее/старее» в пределах сола, лента кадров той же камеры, `extra` под катом. Кнопка «Curiosity variant» показывает случай «есть только full».
- `manifest.html` — хроника миссии из `/manifest`: тепловая полоса всей миссии (клетка = 10 солов) + столбики по солам в диапазоне `from_sol`/`to_sol`, клик по столбику → браузер на этом соле; табличный вид для доступности.
- `styles.css` — токены (цвета светлой/тёмной темы, шрифты системные, шаг отступов 4 px), общие компоненты, заглушки снимков на CSS-градиентах.

## Ключевые решения

- Навигация: Rovers → Photos (последний сол) → Photo; Timeline — второй вход в сол; везде хлебные крошки и вкладки марсоходов (только с данными).
- Порядок карточек на главной — активные первыми (API сортирует по `id`, переупорядочиваем на клиенте).
- Марсоходы с `max_sol = null` фильтруются на клиенте и нигде не показываются (решение владельца 2).
- Сол и земная дата — переключатель «Find by: Sol | Earth date»: активно только одно поле, поэтому 422 «оба сразу» из UI не достижимо.
- «Latest sol» = `sol=max_sol` из Rover через обычный `/photos`, а не `/photos/latest` — так работают все фильтры (у `/latest` нет `sample_type`).
- Камеры — чипы: сверху камеры, снимавшие в этот сол (из `manifest.sols[].cameras`), остальные — под катом и приглушены; на чипе — `total_photos` из `/cameras` с пометкой «по всем солам».
- sample_type — сегменты All / Full / Subframe / Downsampled; прочие значения источника (`mixed`, `chemcam prc`) видны бейджем другого цвета на карточке, но в фильтре их нет (как в контракте).
- Сетка 2/3/4/6 колонок, `per_page` = 24/48/96 (делится на все варианты колонок; в пределах 1–100). Миниатюра в сетке всегда 4:3 с обрезкой, полный кадр — на странице снимка.
- Миниатюра: `images.small` → `medium` → `full`; у Curiosity грузится `full` (лениво).
- Credit — на каждой плитке сетки, под большим кадром и в метаданных.
- Под результатами — строка «API: GET …» с текущим запросом: аудитория — в том числе разработчики.
- Ошибка 422 — человеческий текст по полю из `details` + код и сырой ответ под катом; кнопка «к последнему солу».
- Пустой сол — объяснение и шаги «соседний сол» / «открыть хронику».
- Хроника: один цвет (последовательная шкала 4 ступени по квартилям + «нет снимков»), подсказка при наведении и фокусе, табличный вид; некорректный диапазон (`from > to`) — сообщение до запроса.
- Тема: светлая/тёмная по `prefers-color-scheme` + ручной переключатель в шапке; контраст текста ≥ AA, видимый фокус, подписи у полей, `role="img"`+`aria-label` у заглушек.

## Чего не хватает в API v2 (предложения)

1. **Соседи снимка внутри сола.** Для «новее/старее» и «N из 52» на `photo.html` фронтенду сейчас нужно выгружать весь сол. Предложение: в PhotoDetail поля `prev_id`, `next_id` (в порядке сортировки списка) и `position`/`sol_total`; опционально — с учётом фильтра `camera`.
2. **Счётчики камер за сол.** `/cameras` даёт `total_photos` только по всей миссии, а в `manifest.sols[].cameras` — только коды. Предложение: `cameras` в манифесте как `[{"code", "total_photos"}]` или параметр `sol` у `/cameras`, чтобы на чипах были числа за сол.
3. **Размеры кадра.** Нет `width`/`height` (у Perseverance лежат в `extra.dimension` строкой). Нужны для заглушек нужной пропорции, без «прыжков» сетки и для подписи размеров в переключателе. Предложение: `width`, `height` в Photo (и по размерам в `images`, если известны).
4. **Миниатюры Curiosity.** `small/medium/large` = `null`, сетка грузит полноразмерные файлы. Предложение: обсудить превью (например, свой ресайз/кеш или поле `thumbnail`, если в фиде MSL есть уменьшенные версии).
5. **Местное солнечное время (LMST).** Есть только в `extra` (`lmst`) и не для всех марсоходов. Для энтузиастов это «время на Марсе». Предложение: поле `local_time` в PhotoDetail.
6. **`sample_type` у `/photos/latest`.** Нет фильтра, в отличие от `/photos`. Предложение: добавить для единообразия (пока обходим через `sol=max_sol`).
7. **Дата → сол.** При поиске по `earth_date` с пустым результатом нельзя подсказать ближайший сол со снимками без загрузки манифеста. Предложение: в ответе списка при пустом результате — `nearest_sols: {"before": 2028, "after": 2030}`, либо полагаться на манифест (тогда зафиксировать это как сценарий).
8. **Лёгкий манифест.** У Curiosity >5000 солов, в каждом — массив камер; для тепловой полосы камеры не нужны. Предложение: `?fields=sol,total_photos` или агрегат `?bucket=10`.
9. **Конец миссии.** Для завершённых миссий нет `end_date`/даты последнего контакта, показываем `max_date` как «Last date». Предложение: `end_date` в Rover.
10. **Происхождение данных.** Для Spirit/Opportunity `last_synced_at` — это время разового импорта; полезно различать: `data_source: "sync" | "archive_import"` или отдельное `imported_at`.
11. **CORS.** В контракте не описан; фронтенд на отдельном домене не сможет ходить в API. Нужно решение (разрешённые origin или фронтенд на том же хосте).

## Открытые вопросы владельцу

1. Формат `details` для неизвестной камеры: в общих правилах — список `{"field","message"}`, у `/photos` — «список допустимых кодов». Это коды внутри `message` или отдельная структура? От этого зависит подсказка «доступные камеры» в UI.
2. Солы без снимков в `manifest.sols` отсутствуют или приходят с `total_photos: 0`? (Макет считает, что отсутствуют.)
3. Открывать изображения напрямую по `images.*` (URL NASA) или через `/api/v2/photos/{id}/image?size=` (редирект + кеш)? Второе удобнее для «Open image» и скачивания, первое — для сетки.
4. Ссылка «View on the mission’s raw-image page» ведёт на сайт NASA — допустимо ли с точки зрения «неофициальности» (без логотипов, только текстовая ссылка)?
5. Язык интерфейса — только английский или позже добавить русский?
6. Нужен ли «ночной» режим просмотра (тёмный фон кадра всегда, как сейчас на странице снимка) и полноэкранный просмотр?

## Как смотреть

Открыть `design/mockups/index.html` двойным щелчком или `http://127.0.0.1:8811/index.html` (сервер раздаёт `design/mockups`); остальные экраны — по ссылкам в шапке. Варианты: `photos.html?rover=curiosity`, `manifest.html?rover=curiosity`. Переключатели с пометкой «Mockup» — только для показа состояний, в продукт не входят.

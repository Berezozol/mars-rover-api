# Дизайн: первые наброски фронтенда

Статичные макеты в `design/mockups/`, открываются двойным щелчком или через локальный HTTP-сервер (ссылки относительные). Фронтенд работает только на API v2 (`docs/API.md`). Название — **Sol Index** (утверждено; нейтральное, без знаков NASA/JPL; в подвале — оговорка «неофициальный проект»).

## Решения владельца (2026-11-17)

1. Название **Sol Index** утверждено.
2. Марсоход без данных (`max_sol = null`) в UI скрыт: карточки на главной, вкладки и списки марсоходов на всех экранах, быстрый переход. Сейчас скрыты Spirit и Opportunity — появятся после импорта архива. Состояние карточки «Archive import pending» убрано; на главной одна строка-подсказка «More rovers appear when their archives are imported».
3. Открытие марсохода ведёт на его последний сол — браузер снимков на `max_sol`. Туда ведут главная кнопка карточки, вкладки и пункт «Photos» в шапке; хроника — вторичная ссылка.

## Экраны

- `index.html` — главная: быстрый переход «марсоход + сол», карточки марсоходов из `GET /rovers` (только с данными: Perseverance, Curiosity) + подсказка про будущие архивы, полоса «последнее от Perseverance» из `/photos/latest`, блок для разработчиков (v1 → смена хоста, v2).
- `photos.html` — браузер снимков одного марсохода: сол или земная дата, камеры, sample_type, сетка, пагинация, состояния (переключатель «Mockup» сверху: данные / загрузка / пустой сол / 422). Без `sol` открывается последний сол марсохода. Данные: Perseverance sol 2031 (52 снимка, это и есть последний) и `?rover=curiosity` — снимки Curiosity sol 1000 (856, только `full`) вместо последнего сола 5066 (оговорено в полосе «Mockup»).
- `photo.html` — карточка снимка (PhotoDetail 81234, SUPERCAM_RMI): большой кадр, переключатель размера, метаданные, подпись, credit, источник, «новее/старее» в пределах сола, лента кадров той же камеры, `extra` под катом. Кнопка «Curiosity variant» показывает случай «есть только full».
- `manifest.html` — хроника миссии из `/manifest`: тепловая полоса всей миссии (клетка = 10 солов) + столбики по солам в диапазоне `from_sol`/`to_sol`, клик по столбику → браузер на этом соле; табличный вид для доступности.
- `map.html` — карта маршрута (этап 11; `?rover=perseverance|curiosity|spirit`, `from_sol`, `to_sol`): линия маршрута из `/traverse`, стоянки из `/location` точками, последняя стоянка выделена (ромб с подписью), подсветка диапазона солов (поля «From sol» / «To sol», пресет «Last 100 sols»), подсказка при наведении и фокусе (sol, site/drive, координаты, проезд, всего), выбор стоянки → панель «Selected stop» с кнопкой «Browse sol N photos» (`photos.html?rover=…&sol=N`), список стоянок с пагинацией (по 8, новые сверху — доступная замена карте). Состояния («Mockup» сверху): данные, загрузка, диапазон без стоянок, ошибка сервера (503 `db_unavailable`), «нет данных» (Spirit: `available: false`). Данные — урезанные реальные из `data/locations/` (Perseverance: 708 стоянок и 555 отрезков до сола 2022; Curiosity: 1389 стоянок и 1317 отрезков до сола 5073, у отрезков sol `null`), траектория упрощена (Дуглас–Пекер, допуск ~1,5–2,5 м); данные встроены в файл (~340 КБ).
- В `photo.html` добавлен блок «Location» (`PhotoDetail.location`): мини-карта (весь маршрут Perseverance + точка), бейдж Exact / Approximate, координаты, высота, стоянка (sol/site/drive), ссылка на карту. Переключатель «Mockup · location»: `exact: false` (по умолчанию), `exact: true`, `location: null` (блок скрыт целиком, без пустого заголовка). Site/drive снимка в макете заменены с 112/1874 на 93/412: стоянок site 112 в данных нет (маршрут кончается солом 2022), так что по контракту `location` для него был бы `null`.
- Во всех шапках и на карточках марсоходов главной добавлена ссылка «Route map».
- `styles.css` — токены (цвета светлой/тёмной темы, `--map-*` для карты, шрифты системные, шаг отступов 4 px), общие компоненты, заглушки снимков на CSS-градиентах.

## Ключевые решения

- Навигация: Rovers → Photos (последний сол) → Photo; Timeline — второй вход в сол; везде хлебные крошки и вкладки марсоходов (только с данными).
- Порядок карточек на главной — активные первыми (API сортирует по `id`, переупорядочиваем на клиенте).
- Марсоходы с `max_sol = null` фильтруются на клиенте и нигде не показываются (решение владельца 2).
- Сол и земная дата — переключатель «Find by: Sol | Earth date»: активно только одно поле, поэтому 422 «оба сразу» из UI не достижимо.
- «Latest sol» = `sol=max_sol` из Rover через обычный `/photos`, а не `/photos/latest` — так работают все фильтры (у `/latest` нет `sample_type`).
- Камеры — чипы: сверху камеры, снимавшие в этот сол (из `manifest.sols[].cameras`), остальные — под катом и приглушены; на чипе — `total_photos` из `/cameras` с пометкой «по всем солам».
- sample_type — сегменты All / Full / Subframe / Downsampled; прочие значения источника (`mixed`, `chemcam prc`) видны бейджем другого цвета на карточке, но в фильтре их нет (как в контракте).
- Сетка 2/3/4/6 колонок, `per_page` = 24/48/96 (делится на все варианты колонок; в пределах 1–100). Миниатюра в сетке всегда 4:3 с обрезкой, полный кадр — на странице снимка.
- Миниатюра: `images.small` → `medium` → `full`; у Curiosity грузится `full` (лениво).
- Credit — на каждой плитке сетки, под большим кадром и в метаданных.
- Под результатами — строка «API: GET …» с текущим запросом: аудитория — в том числе разработчики.
- Ошибка 422 — человеческий текст по полю из `details` + код и сырой ответ под катом; кнопка «к последнему солу».
- Пустой сол — объяснение и шаги «соседний сол» / «открыть хронику».
- Хроника: один цвет (последовательная шкала 4 ступени по квартилям + «нет снимков»), подсказка при наведении и фокусе, табличный вид; некорректный диапазон (`from > to`) — сообщение до запроса.
- Тема: светлая/тёмная по `prefers-color-scheme` + ручной переключатель в шапке; контраст текста ≥ AA, видимый фокус, подписи у полей, `role="img"`+`aria-label` у заглушек.

## Карта маршрута: решения (этап 11)

- Подложки нет: SVG на плоском фоне `--map-bg`, сетка широта/долгота с подписями (шаг подбирается по масштабу), масштабная линейка, стрелка севера. Ни одного внешнего запроса и ассета; макет полностью рабочий без подложки.
- Проекция — равнопромежуточная с поправкой cos(широты): на масштабе кратера искажения незаметны; 1° широты = 59,16 км (R = 3389,5 км) для линейки.
- Маршрут — одна фоновая линия + поверх неё подсвеченная часть диапазона; стоянки — точки (круглые концы нулевых отрезков, один `<path>`, быстро и для 1400 точек). Различие не только цветом: ромб «последняя», кольцо «выбрана», толщина линии.
- Подсветка диапазона: у Perseverance — по `properties.sol` отрезков; у Curiosity sol на отрезках `null`, поэтому крайние стоянки диапазона привязываются к ближайшим вершинам маршрута и подсвечивается участок между ними. Это приближение, на экране есть жёлтая пометка. Точнее — см. предложение 12.
- Стоянка — конец проезда: в панели оговорено, что фото этого сола могли сниматься и на других стоянках.
- Клик — выбор, не переход: на тач-экране нет hover, а прямой переход мешал бы смотреть подробности. Переход — кнопкой в панели. С клавиатуры: фокус на карту, ←/→ шагают по стоянкам диапазона, Home/End — первая/последняя, +/− масштаб, Esc снять выбор. Все стоянки также доступны списком (таблицей) справа — это неграфическая альтернатива карте.
- Масштаб колёсиком только с Ctrl/⌘ (не перехватывает прокрутку страницы); перетаскивание — мышью; на касании — кнопки ± и список (однопальцевое перетаскивание отдано прокрутке страницы).
- Диапазон валидируется до запроса (`from_sol > to_sol` — 422 в контракте). Диапазон без стоянок (например, у Perseverance солы 2010–2021 между двумя стоянками) — не ошибка, а пояснение поверх карты и кнопка «Clear range».
- Плашка «Position data ends at sol 2022. Photos reach sol 2031»: источник обновляется нерегулярно, `source_max_sol` < `max_sol` — норма, а не сбой.
- «Distance (source)» — `dist_total_m` последней стоянки с пометкой источника: по контракту оно не обязано расти от стоянки к стоянке.
- Ingenuity: вкладка «Soon» заменена рабочей ссылкой «Flights» (см. раздел «Ingenuity (этап 12)»).
- Spirit и Opportunity на вкладках скрыты (решение владельца 2), но прямая ссылка `map.html?rover=spirit` показывает состояние «No location data» (`available: false`); когда архивы будут импортированы и вкладки появятся, оно уже готово.
- Мини-карта в карточке снимка: весь маршрут без зума + точка; при `exact: false` вокруг точки пунктирный круг (условный порядок длины одного проезда) и текст «taken while driving after the stop …»; при `location: null` блока нет совсем.

### Варианты подложки (нужно решение владельца)

1. **Без подложки** (сейчас). Плюсы: ноль зависимостей и прав, быстро, офлайн, нейтрально по «неофициальности». Минусы: нет рельефа и ориентиров, карта — «схема».
2. **Свои предрендеренные тайлы из публичных орбитальных мозаик** (например, CTX/HiRISE-мозаики кратеров Езеро и Гейла) — статический набор тайлов или один файл PMTiles рядом с фронтендом, только для двух районов (порядка десятков МБ). Плюсы: нет внешних запросов, работает за Tailscale Funnel, выглядит лучше. Минусы: нужно проверить лицензии и формулировки авторства каждой мозаики, отдельная работа по подготовке (data-engineer), размер репозитория/образа, районы маршрута со временем расширяются (Curiosity уходит дальше по склону горы Шарп).
3. **Готовый тайловый сервис** (в т.ч. тайлы JPL/MMGIS, Trek, OpenPlanetary). Плюсы: минимум работы, весь Марс. Минусы: запросы из браузера пользователя уходят третьей стороне (приватность), условия использования и доступность не гарантированы, CORS, зависимость от JPL в «неофициальном» проекте.

Рекомендация: вариант 1 — основной и единственный по умолчанию; после проверки лицензий добавить вариант 2 как необязательный слой «Imagery» (выключатель, по умолчанию выключен) только для Езеро и Гейла. Вариант 3 не брать. Структура готова: подложка — отдельная группа под маршрутом в том же SVG (в пиксельных координатах с той же проекцией).

## Ingenuity (этап 12)

Данные: `Flight`, `GET /rovers/ingenuity/flights`, `PhotoDetail.flight`, Rover `ingenuity` (`status: complete`, `data_source: archive`). Значения полётов — настоящие, из `data/ingenuity/flights.csv` (72 строки); `total_photos` в макете выдуманы (в CSV их нет).

- `flights.html` — «Ingenuity flights». Плитки: полётов 72 (сол 58–1035), налёт 2 ч 8 мин 51 с (7731 с), дистанция 16,97 км, макс. высота 24 м (полёт 61). Таблица всех 72 полётов: Flight, Sol, Date (PT), Distance, Max altitude, Max speed, Duration (м:сс), From → to, Photos (ссылка на `photos.html?rover=ingenuity&sol=N`). Сортировка: заголовки-кнопки (`aria-sort`) и поле «Sort by» (на телефоне заголовков нет). Рекордные строки (самый высокий, длинный, быстрый) подсвечены и подписаны словом, не только цветом. Якоря `#flight-N` (из карточки снимка). Состояния («Mockup»): данные, загрузка, пусто, ошибка 503 `db_unavailable`. На телефоне (до 760 px) таблица превращается в карточки полётов, подписи берутся из `data-label`.
- Единицы: итоги — км (16,97 км), по полёту — метры (по контракту `distance_m`, у 27 полётов дистанция меньше 150 м, км там нечитаемы); скорость м/с; высота м; футы и мили не показываем (API их не отдаёт). Длительность — м:сс, секунды в `aria-label`.
- `to: null` (27 полётов): в таблице тире с подсказкой «в журнале не указана площадка посадки», стрелка скрыта для скринридера словом «to». Не пишем «та же площадка»: контракт этого не гарантирует.
- Итоги считаются на клиенте из `items`: все 72 приходят одним ответом, отдельного агрегата не нужно.
- `map.html`: вкладка «Ingenuity · Soon» заменена ссылкой «Flights» (`flights.html`), показывается только на Perseverance (вертолёт летал рядом с ним; у Ingenuity своей карты нет, `location` всегда `null`). Во всех шапках добавлен пункт «Flights».
- `map.html`, панель «Selected stop»: кнопки «Photos of sol N» (прежнее «Browse sol N photos») и «Photos at this stop» (`photos.html?rover=…&site=…&drive=…`), под ними пояснение разницы. Вторая кнопка нужна фильтру `site`/`drive` в `/photos`, которого в контракте нет (предложение 13); пока в макете это целевое поведение. Если фильтра не будет, кнопку убрать.
- `map.html`, шапка: полоса «Latest position» из `GET /location?latest=true` (сол, site/drive, координаты, высота; «Show on map» выбирает стоянку и центрирует, «Photos of sol N»). Если `source_max_sol` < `max_sol` — пометка «Latest published stop; photos reach sol …». Прячется в состояниях загрузки/ошибки/«нет данных». Заменяет предложение 15 как решённое: полный `/location` ради одной точки больше не нужен на главной (но карте он всё равно нужен целиком).
- `photo.html`: переключатель «Mockup · rover» (Perseverance / Ingenuity в день полёта / Ingenuity без полёта). При `flight: N` — бейдж «Flight N» рядом с `#id` в шапке карточки и блок «Flight» (номер из 72, дата PT, маршрут, дистанция и высота, длительность, ссылки на все снимки сола и на таблицу полётов) с оговоркой «связь только по солу: кадр мог быть до или после полёта». При `flight: null` — короткая строка «No flight on this sol». Блок «Location» у Ingenuity скрыт (`location: null`), site/drive — «—». Данные блока «Flight» в макете взяты из `Flight 9`; в реальности они из `GET /rovers/ingenuity/flights/9` (или из списка, он кешируется 5 минут).
- `index.html`: карточка Ingenuity — бейджи «Complete» и «Imported» (`data_source: archive`), вместо «Synced …» строка «Imported <дата> · one-off archive, not updated», вместо «Cameras/Latest sol» те же поля плюс «Flights 72»; главная кнопка — «72 flights» (у вертолёта полёты важнее «последнего сола»), Photos и Timeline — вторичные. Сетка карточек: 3 колонки от 960 px (в `styles.css`). Порядок: активные, затем завершённые.

### Открытые вопросы (Ingenuity)

1. «Latest sol 1069», «14 553 фото», «2 камеры» на карточке — в макете оценка (из страницы 0 фида и из `docs/API.md`); сверить с реальным `/rovers/ingenuity`.
2. Нужны ли `photos.html`/`manifest.html` для Ingenuity: ссылки на них поставлены, макетов под вертолёт нет. Камеры HELI_NAV (чёрно-белая навигационная, 640×480) и HELI_RTE (цветная) подойдут существующим чипам; сетка 4:3 их кадр не искажает. Показывать ли на плитках снимков бейдж «Flight N» для кадров дня полёта? (Сейчас только на странице снимка.)
3. Показывать ли в браузере снимков Ingenuity в день полёта отдельную строку «Flight N · 166 s · 625 m» над сеткой (данные те же, один запрос `/flights/{n}`)? Рекомендую да.
4. Название вкладки/пункта «Flights» в общей шапке относится только к Ingenuity; если появятся другие виды полётов или меню разрастётся, перенести в меню марсохода.
5. Подпись `credit` у Ingenuity в макете «NASA/JPL-Caltech» — проверить по фиду.
6. Страница `flights.html` не фильтрует по году/площадке: для 72 строк сортировки достаточно. Графики (высота по полётам) — отдельное решение, в этот макет не входят.

### Чего не хватает в API (Ingenuity)

- Фильтр `site`/`drive` в `/photos` — для «Photos at this stop» (то же, что предложение 13).
- Итоги по полётам (налёт, дистанция) считаются на клиенте; отдельный агрегат не нужен, пока список отдаётся целиком.
- У `Rover` для Ingenuity хотелось бы счётчик `flights_count` на карточке главной, иначе для «72 flights» на главной нужен лишний запрос `/flights`. Предложение: `flights_count` (или брать длину `/flights`, он кешируется).
- `PhotoDetail.flight` отдаёт только номер: для блока «Flight» нужен второй запрос `/flights/{n}` (дёшево, кешируется). Альтернатива — вложенный объект `flight_info`; не настаиваю.
- В `Flight` нет `max_altitude` в футах и т. п. — и не надо; но нет «Total air time» для сравнения с миссией: считаем сами.

## Образцы Perseverance (этап 13)

Данные: `Sample`, `GET /rovers/perseverance/samples`, `PhotoDetail.samples` (черновик `docs/proposals/stage-13-samples.md`, раздел 3). Значения в макетах настоящие — разобраны из сохранённой страницы NASA `data/samples/rock-samples.html` (30 строк: на борту 21, в депо 9; rock core 27, regolith 2, atmospheric 1; солы 164-1441, № 29-30 с `TBD`). Выдуманы: `total_photos` (140-559, в странице их нет) и `location.match` (у № 25 и 8 `exact`, у № 2 `nearest_before`, у остальных `by_sol` — чтобы показать все три ветки). `location` посчитан в макете как последняя стоянка со `sol` не больше сола образца из встроенных стоянок `map.html`.

- `samples.html` — «Perseverance rock samples». Плашка источника «Source: NASA, Mars Rock Samples page» со ссылкой, датой правки страницы (`source_updated_at`) и датой проверки (`updated_at`) + пометка «may lag the mission». Жёлтая полоса, если последний сол в таблице сильно отстаёт от `max_sol` (сейчас 1441 против 2031) и если есть `TBD`. Плитки: всего (диапазон солов), на борту, в депо, по типам. Фильтры-чипы «Status» и «Type» (aria-pressed, счётчики, всё на клиенте, 30 строк). Таблица: №, имя + feature, место, тип/порода, дата + сол, высота, статус-бейдж, ссылки (Dossier PDF, «Photos of sol N (total_photos)», «Photos of the tube» = `photos?sol=N&camera=CACHECAM`). Состояния: данные, загрузка, пусто («not loaded yet», `items: []`), ошибка 503 `db_unavailable`, «нет совпадений с фильтрами».

Переключатель «Samples» над картой, пункт легенды «Sample sealed here», подсказка и список стоянок отмечают стоянки с образцами. В «Selected stop» блок «Sample sealed here» / «N samples sealed here»: карточка на образец (номер, имя, статус, тип, порода, сол и дата, `feature_name`, пояснение по `match`, «Photos of the tube», «Photos of sol N»). ### Решения (образцы)

- Одна страница, а не вкладка с картой: карта и таблица связаны ссылками (`#sample-N` и `map.html?from_sol=&to_sol=`), панель на карте показывает те же поля.
- Фильтры и итоги считаются на клиенте: по контракту фильтров нет, 30 строк приходят одним ответом.
- `status: null` / `sample_type: null` (незнакомое значение страницы) показываются текстом страницы (`current_location`, `sample_type_label`) без цветного бейджа; в чипы такие строки не попадают.
- Имена не разбираются: `Ha'ahóni (aka "Hahonih")`, `Ch’ał outcrop` — как на странице.
- Высота: число + «cm» или `height_note` как есть (№ 29), иначе тире. Дюймы не показываем (API их не отдаёт).
- Дата без часового пояса: в таблице как есть, сол — надёжный ключ (сноска под таблицей).
- `dossier_url: null` (№ 26-30): «No dossier yet» вместо пустой ячейки.
- «Photos of the tube» всегда ведёт на `camera=CACHECAM` того же сола. У сола 377 (№ 9) CACHECAM нет (по отчёту архитектора) — получится пустой сол с обычным пояснением «за этот сол снимков нет».
- Связь с картой честная: `by_sol` пишет «nearest published stop; the rover may have moved since»; `exact` — «Sealed at this stop».
- Авторство: подпись «Source: NASA» — текстовая ссылка, без логотипов; в подвале прежняя оговорка про неофициальность.

### Вопросы (образцы)

1. Несколько образцов на одной стоянке — норма (в макете 28 образцов на 21 стоянке: №№ 2 и 3, 4 и 5 и т. д. по `by_sol`), потому что стоянки публикуются по концу проезда, а образцы берут в солы без проезда. Нужно ли в API выдавать `location` с `match: by_sol` как «стоянка по солу» или показывать такие образцы на карте только пунктирным маркером (приблизительно)? Сейчас маркер один и тот же, различие только в тексте панели. Решение зависит от доли `exact` на проде (задача `data-engineer`).
2. Показывать ли «Photos of the tube», если в соле нет CACHECAM? Для этого фронтенду нужен манифест (`manifest.sols[].cameras`) или поле в Sample; предлагаю `has_tube_photos: bool` либо просто полагаться на пустое состояние.
3. `total_photos` на строке — снимки всего сола (сотни), а не снимки пробирки; подпись «Photos of sol N (…)» это оговаривает. Нужен ли отдельный счётчик CACHECAM (`tube_photos`)? Предложение к API, не обязательное.
4. Источник отстаёт на месяцы (последний образец — сол 1441, сейчас ~2031). Полоса «may be behind» появляется при разрыве > 100 солов (порог условный, считается на клиенте из `max_sol`); подходит ли порог?
5. Показывать ли образец на карточке снимка и для соседних солов (± 1)? Сейчас строго `samples` того же сола, как в контракте.

### Чего не хватает в API (образцы)

- Нет поля «есть ли снимки CACHECAM в этот сол» (см. вопрос 2).
- Нет `max_sol` в ответе `/samples`: полоса «page may be behind» берёт его из `/rovers/perseverance` (лишний, но кешируемый запрос; на главной он и так есть).
- `PhotoDetail.samples` отдаёт только номера: блок на `photo.html` берёт имя/статус/тип из списка `/samples` (кеш час) или из `/samples/{n}`. Альтернатива — вложенный объект; не настаиваю.

## RSS (этап 16)

Экраны: `photos.html` (кнопка «Subscribe (RSS)»), `photo.html` (ссылка «Subscribe to this camera»). Остальные экраны не менялись.

### Решения (RSS)

- **Кнопка в шапке страницы марсохода**, справа от статуса, а не в блоке фильтров: подписка относится к марсоходу, а не к выдаче одного сола. На телефоне — на всю ширину, панель раскрывается под ней (без плавающего окна).
- **Поповер, не модальное окно**: кнопка с `aria-expanded`/`aria-controls`, фокус уходит в поле со ссылкой, Esc и клик снаружи закрывают, фокус возвращается на кнопку.
- **Лента повторяет фильтры страницы**: `camera` и `sample_type` из текущих фильтров; `sol`/`earth_date` не входят (лента про «новое», а не про сол). Подпись «RSS: Perseverance · NAVCAM_LEFT · full» (без камеры — «all cameras»). При смене фильтров открытая панель обновляется.
- **«One per sol» / «One per photo»** — сегментированный переключатель; по умолчанию сол (как `group=sol` в API), параметр по умолчанию в ссылке опускается. Подсказка под переключателем честно предупреждает, что «one per photo» шумная (до 50 записей; в день бывает сотни снимков).
- **Объяснение для неспециалистов** — одна фраза над ссылкой: RSS-читалка сама сообщает о новых снимках, достаточно вставить ссылку.
- **Копирование**: поле только для чтения (выделяется по фокусу) + кнопка Copy; результат — в `role="status"`. Если буфер обмена недоступен, ссылка выделяется и подсказывается Ctrl+C.
- **Адрес ленты** абсолютный (`origin` текущего хоста; в макете при открытии с диска — пример `*.ts.net`), как в контракте.
- **`photo.html`**: ссылка с RSS-значком в строке «Camera» метаданных, ведёт на `feed.xml?camera={code}` (без `group`, т.е. по солам). У Ingenuity ссылки нет.
- **Архивные марсоходы** (Spirit, Opportunity, Ingenuity): элемент не рисуется вообще (не disabled) — нет смысла дразнить функцией, которой не будет. Показ: кнопка «Mockup · Archive rover (no RSS)» на `photos.html`, вариант Ingenuity на `photo.html`. Реально это определяется тем, что `status` не `active` (см. предложение ниже).
- Значок RSS — простой inline SVG, не логотип; цвета через переменные темы.

### Чего не хватает в API (RSS)

- Нет явного признака «у марсохода есть лента» в `Rover`. Макет считает так: лента есть у `status = active` и не-Ingenuity; для Ingenuity (`completed`) это сработает, но правило хрупкое. Предложение: `feed_available: bool` (или `has_feed`) в Rover.
- Если RSS нужен «для всех фильтров сразу» (например, несколько камер) — контракт даёт одну камеру; в макете один выбор. Достаточно для первой версии.
- Для подписи «сколько записей будет в день» не хватает оценки; в макете она не показана, только качественное предупреждение.

### Вопросы (RSS)

1. Нужна ли в `photo.html` ссылка на ленту всего марсохода (без камеры) рядом с кнопкой на `photos.html`? Пока есть только на странице марсохода.

## Поиск, «рядом с точкой», статистика (этап 19)

Экраны: `search.html`, `near.html`, `stats.html`; в шапке всех макетов добавлены «Search» (после Photos) и «Stats» (после Samples); `map.html` получил переключатель режима «Browse stops | Photos near a point» и кнопку «Photos within 1 km» в панели выбранной стоянки. Переключатели «Mockup» — только для показа состояний. Данные генерируются в странице; суммы по марсоходам сходятся с `Rover.total_photos`, форма по месяцам выдумана, итоги в поиске — оценки.

### Навигация
- «Search» и «Stats» — пункты главной навигации (не вкладки марсохода: они про несколько марсоходов). «Рядом с точкой» — режим экрана «Route map» (переключатель под вкладками марсохода), а не отдельный пункт: общая карта, общий выбор марсохода. В реализации это может быть одна страница `RouteMap` с параметрами `near`/`radius_km` в адресе.
- Связки: карточка стоянки → «Photos within 1 km»; строка камеры и карточка марсохода в Stats → Search с теми же фильтрами (`search.html?rovers=…&camera=…`); Search понимает те же параметры в адресе.

### Search
- Фильтры в одной панели; на телефоне сворачиваются в кнопку «Filters» (`aria-expanded`) со строкой-резюме и счётчиком активных; применяются кнопкой «Search», не на каждый клик (тяжёлые запросы).
- Марсоходы — чипы, минимум один; если выбраны все, `rovers` не отправляется. Камеры — чипы по марсоходам, до 10 (11-й блокируется), снятый марсоход убирает свои камеры.
- Сортировка по умолчанию на клиенте — `-taken_at` («Newest on Mars»), а не серверный `-sol`: при нескольких марсоходах `-sol` смешивает эпохи (подсказка появляется при выборе `sol`-сортировок).
- Время суток: «Any / Golden hour / Custom window» — взаимоисключающие сегменты, поэтому 422 «golden_hour + local_time_*» недостижим из UI. Заметка о покрытии (~половина Curiosity, Perseverance до 2026-11-20 без local_time) и о переходе через полночь при `min > max`; `min = max` — ошибка до запроса.
- Размер кадра: предупреждение «у Curiosity размера нет, снимки не подойдут».
- Одно и то же значение «от» и «до» сола отправляется как `sol` (лёгкий запрос). Значок «May be slow» — упрощённая копия правил тяжёлых поисков из API.md.
- Пагинация — `Pager` с «Go to page»; число страниц режется до `10 000 / per_page`, над сеткой заметка «Only the first 10,000 photos can be browsed».
- Состояния: загрузка, пусто (причины по активным фильтрам), 422 (человеческий текст + сырой ответ; два примера: окно времени и лимит страниц), 503 `service_busy`: отсчёт `Retry-After` (5 с), кнопка «Try again» включается по окончании, скринридеру сообщается дважды (в начале и по готовности), советы сузить поиск и кнопка «убрать фильтры времени и размера». Тексты `message` в 422-примерах выдуманы.

### Photos near a point
- Клик по карте или стоянке ставит точку (по стоянке — прилипает), ту же точку задают поля широты/долготы и «Or stop of sol N» (клавиатурная альтернатива), «Latest stop»; стрелки на карте шагают по стоянкам. Полупрозрачный пунктирный круг радиуса и подсветка стоянок внутри круга показывают, что именно ищется: снимки, сделанные на стоянках в радиусе, а не «то, что видно на кадре».
- Радиус: логарифмический ползунок 0,01-50 км + числовое поле (по умолчанию 1), риски 0,01 / 0,1 / 1 / 10 / 50; вне диапазона — ошибка у поля.
- Рядом: «Inside the circle» — число стоянок и диапазон солов (считает клиент по `/location`); при нуле — расстояние до ближайшей стоянки и кнопка «Widen».
- Покрытие — сворачиваемый блок «What is covered»: у Curiosity около половины снимков без стоянки, у Perseverance — посадка (солы ≤ 9), привязка к месту, где стоял марсоход, снимки в пути. Только curiosity/perseverance: вкладки только они; устаревшая ссылка на Spirit показывает 422 (состояние макета).
- Результаты ниже карты, фильтры: камера, диапазон солов, порядок (`-sol`/`sol`), per_page; камера/сол вместе с `near` — «May be slow».

### Stats
- Два запроса: `group_by=rover` для сводки и карточек, затем вкладка «By month / By year / By camera» (запрашивается выбранная). Фильтры: марсоходы, камеры (до 10), сол или земная дата (переключатель, вместе не бывают), «Full frames only» (`sample_type=full`).
- Диаграмма: по марсоходу отдельная (small multiples) — один цвет, без легенды, у каждой своя шкала (иначе Ingenuity не видно). Периоды без снимков API не отдаёт — клиент добавляет нули, чтобы время шло непрерывно. Доступность: `role="img"` с текстовым итогом, чтение столбика стрелками/наведением в строке `aria-live`, горизонтальная прокрутка на телефоне (фокусируемая), переключатель «Chart | Table» (таблица с пагинацией по 12 строк, те же числа). Цвета — токены `--chart-*` (светлая/тёмная темы).
- По камерам — таблица с полосками (доля внутри марсохода), сортировка по «Photos» (`aria-sort`), ссылка «Search».
- Пояснение про даты: статистика считает по дате сола, поиск — по дате снимка; у границы суток числа могут слегка расходиться. Верхнеуровневые `sols_with_photos` — сумма по марсоходам, подписано.
- Состояния: загрузка, пусто (`total_photos: 0`, `groups: []`), 422 (стала ссылка с солами и датами), 503.

### Чего не хватает в API (этап 19)
1. `local_time` в Photo из списков (сейчас только в PhotoDetail): без него нельзя подписать «17:40 LMST» на плитке поиска по времени суток и проверить попадание в окно.
2. Для `near`: в Photo/списке `site`, `drive` или расстояние до точки — чтобы подписать, на какой стоянке снят кадр; сейчас плитка знает только сол.
3. `nearest_sols` и «причина пустоты» есть только у списка марсохода; для `/photos` пустой ответ не объясняет, какой фильтр обнулил результат (причины в макете угадываются на клиенте). Предложение: счётчики «сколько осталось без последнего фильтра» либо флаг `heavy`/`coverage` в ответе.
4. Признак тяжёлого поиска: макет копирует правила из API.md на клиенте — хрупко. Предложение: заголовок/поле `X-Search-Cost: heavy` или ручка оценки.
5. `/photos/stats`: нет ограничения «по `rovers` при `group_by=camera` — список камер выбранных марсоходов» — фронт берёт его из `/cameras` по каждому марсоходу (3 запроса); приемлемо.
6. Ответ 503 `service_busy` нужно читать из заголовка `Retry-After` (CORS: `Access-Control-Expose-Headers`, если фронтенд когда-нибудь на другом origin).
7. Фронтенд должен заполнять нулями пропущенные периоды `group_by=month|year`; параметр `fill=true` упростил бы клиент (необязательно).

### Вопросы владельцу
1. Сортировка по умолчанию в поиске: «Newest on Mars» (`-taken_at`) или серверная `-sol`? Рекомендация: `-taken_at` — но с камерой и без сола он «тяжёлый» и чаще даёт 503; при выбранной камере и без сола можно показывать подсказку про сол. Оставить `-taken_at`.
2. «Рядом с точкой» — режим карты (как в макете) или отдельный пункт навигации? Рекомендация: режим карты.
3. Показывать ли в Search выбор Ingenuity? В макете да (его солы — солы Perseverance, подсказка есть). Рекомендация: да.
4. Нужна ли в Stats вкладка по солам/«heat» вместо дублирования Timeline? Рекомендация: нет, Timeline остаётся единственным местом для солов.
5. Единицы радиуса: километры (как в API) без переключателя на мили — оставить?

Под формой — текст о данных (раздел 4.1 спецификации, по-английски). Ловушка `website`: вне экрана (`left:-10000px`), `aria-hidden`, `tabindex=-1`, `autocomplete=off`; чекбокс «show honeypot field» в панели макета её показывает.
- `/keys/confirm`: «Ready» (кнопка «Show my key», запрос только по нажатию), загрузка, ключ (предупреждение «Save it now…», кнопка Copy с запасным выделением для Ctrl+C, пример `curl` с `X-Api-Key`), `409` (предложение «Replace my keys…», предупреждение, что оба ключа перестанут работать сразу; ссылка использована не была), `400` (одно сообщение для просроченной, использованной и неизвестной ссылки), `403` (блокировка).
- `/keys/manage`: поле ключа (`type=password`, переключатель «show», подсказка, что ключ хранится только в памяти страницы), загрузка, кабинет (адрес, список ключей с «Revoke» и подтверждением на месте, «Create a new key», кнопка отключена при двух активных, использование и лимиты, «Delete my account…» с чекбоксом-подтверждением), «New key issued» (ключ один раз), `401` неизвестный / отозван, `403`, «Account deleted».
- `/keys/delete`: форма адреса (ловушка, `422/429/503`, «sent» и «mail delayed» с нейтральным текстом «If … has an account»), по ссылке — «Delete your data?» с красной кнопкой, «Deleting», «Deleted», `400`.

**Решения для frontend-dev.**
- Токен читается из `location.hash` и сразу убирается `history.replaceState`; страница `/keys/confirm` и `/keys/delete` имеет `<meta name="referrer" content="no-referrer">`. Запрос уходит только по кнопке.
- Ключ из поля на `/keys/manage` и показанный ключ — только в состоянии компонента; не в `localStorage`/`sessionStorage`/cookie/URL; «Sign out» очищает поле.
- Подтверждения — на месте (блок под строкой), не модальные окна: фокус переходит в блок, Cancel возвращает фокус на кнопку. Удаление учётной записи — чекбокс «I understand…» + красная кнопка; печатать адрес не заставляем (неудобно на телефоне).
- Текст у `429`/`503` считается из `Retry-After` (секунды → минуты/часы, округление вверх); `Retry-After` с другого origin не виден, но интерфейс на том же источнике.
- Цвета статусов — только вместе со словами (Active / Revoked); красная кнопка `btn-danger` — только для необратимых действий.
- После смены состояния фокус уходит на заголовок нового состояния (`tabindex=-1`) или на поле с ошибкой; сообщения об ошибках — `role="alert"`, «Sending…» — `role="status"`.
- Ширина 360 px: всё в одну колонку, `.narrow` (до 640 px), без горизонтальной прокрутки; тёмная тема — токены.
- Название «Show my key» — как в спецификации; «Create a new key» вместо «New key» — глагол яснее.

**Данные зашиты в макет, к API не подключено.** Формы ответов — как в `docs/API.md` (`202`, `key`/`key_info`/`account`, `GET /account`: `keys`, `usage`, `limits`); значения (id 39/41/44/45, даты декабря 2026, `today: 312`, `last_30_days: 10450`, `120/10000/8`) — примеры; тексты `message` ошибок выдуманы; `Retry-After` (2520, 14400) выдуманы. Ключ — плейсхолдер `si_EXAMPLE…`, адрес `user@example.org`. Различия с живым ответом: настоящий `prefix` — первые 11 символов ключа (в макете `si_EXAMPLEE/F/G`), «Last used» приходит с задержкой до минуты.

**Чего не хватает в API (предложения).**
1. Текст о данных (4.1) содержит `MAIL_PROVIDER_NAME` и срок хранения учётных записей (24 месяца): в макете они зашиты текстом «Google (Gmail)» и «24 months». Если провайдер сменится, интерфейс разойдётся с `/developers`. Предложение: отдавать оба значения (например, `GET /api/v2/keys/info` или поля в `/llms.txt`/конфиге сборки) либо договориться, что текст один и правится в двух местах.
2. Интерфейс не может узнать, включена ли регистрация (`KEY_SIGNUP_ENABLED`, почта): при `404` на `/keys/requests` экран «Get an API key» нужно показывать как «Key signup is not open yet». Это третье состояние, в макете его нет; предложение: флаг в `GET /api/v2/` или любой ручке общей информации, чтобы скрывать ссылки в подвале заранее.
3. `GET /account` не говорит, каким из ключей сделан запрос: нельзя пометить «this key» в списке (сравнение по `prefix` на клиенте — приближение) и предупредить «вы отзываете ключ, которым вошли». Предложение: `current_key_id`.
4. Сколько писем осталось на адрес за сутки не отдаётся (по замыслу, из-за перечисления адресов): текст «up to 3 messages per day» постоянный.
5. У отозванных ключей нет причины (`revoke_reason`: owner / replaced / admin): показываем только дату. Предложение: отдавать причину в `keys[]`, чтобы писать «replaced by a new key».

## Чего не хватает в API v2 (предложения)

1. **Соседи снимка внутри сола.** Для «новее/старее» и «N из 52» на `photo.html` фронтенду сейчас нужно выгружать весь сол. Предложение: в PhotoDetail поля `prev_id`, `next_id` (в порядке сортировки списка) и `position`/`sol_total`; опционально — с учётом фильтра `camera`.
2. **Счётчики камер за сол.** `/cameras` даёт `total_photos` только по всей миссии, а в `manifest.sols[].cameras` — только коды. Предложение: `cameras` в манифесте как `[{"code", "total_photos"}]` или параметр `sol` у `/cameras`, чтобы на чипах были числа за сол.
3. **Размеры кадра.** Нет `width`/`height` (у Perseverance лежат в `extra.dimension` строкой). Нужны для заглушек нужной пропорции, без «прыжков» сетки и для подписи размеров в переключателе. Предложение: `width`, `height` в Photo (и по размерам в `images`, если известны).
4. **Миниатюры Curiosity.** `small/medium/large` = `null`, сетка грузит полноразмерные файлы. Предложение: обсудить превью (например, свой ресайз/кеш или поле `thumbnail`, если в фиде MSL есть уменьшенные версии).
5. **Местное солнечное время (LMST).** Есть только в `extra` (`lmst`) и не для всех марсоходов. Для энтузиастов это «время на Марсе». Предложение: поле `local_time` в PhotoDetail.
6. **`sample_type` у `/photos/latest`.** Нет фильтра, в отличие от `/photos`. Предложение: добавить для единообразия (пока обходим через `sol=max_sol`).
7. **Дата → сол.** При поиске по `earth_date` с пустым результатом нельзя подсказать ближайший сол со снимками без загрузки манифеста. Предложение: в ответе списка при пустом результате — `nearest_sols: {"before": 2028, "after": 2030}`, либо полагаться на манифест (тогда зафиксировать это как сценарий).
8. **Лёгкий манифест.** У Curiosity >5000 солов, в каждом — массив камер; для тепловой полосы камеры не нужны. Предложение: `?fields=sol,total_photos` или агрегат `?bucket=10`.
9. **Конец миссии.** Для завершённых миссий нет `end_date`/даты последнего контакта, показываем `max_date` как «Last date». Предложение: `end_date` в Rover.
10. **Происхождение данных.** Для Spirit/Opportunity `last_synced_at` — это время разового импорта; полезно различать: `data_source: "sync" | "archive_import"` или отдельное `imported_at`.
11. **CORS.** В контракте не описан; фронтенд на отдельном домене не сможет ходить в API. Нужно решение (разрешённые origin или фронтенд на том же хосте).

12. **Связь отрезков маршрута со стоянками.** У Curiosity `properties.sol` всегда `null`, и подсветка диапазона солов приближённая. Предложение: в `properties` отрезка — `from`/`to` как `{site, drive}` (у Perseverance источник даёт `fromRMC`/`toRMC`; для Curiosity можно вывести по порядку) либо вычислять `sol` для Curiosity на бэкенде по ближайшим стоянкам.
13. **Фильтр фото по стоянке.** «Фото, снятые на этой стоянке» требуют `site`/`drive` в `/photos` (сейчас фильтры — `sol`, `camera`, `sample_type`, дата). Предложение: `site` и `drive` (или `drive_from`/`drive_to`). Пока карта ведёт на весь сол.
14. **Размер ответа.** `/traverse` отдаётся целиком: исходные файлы 1,7 МБ (Perseverance) и 1,4 МБ (Curiosity), 36 тыс. и 27 тыс. вершин; для карты хватает ~4 тыс. Предложение: gzip (обязательно) и необязательный параметр `simplify` (допуск, м) либо уровни детализации.
15. **Последняя стоянка без полного списка.** Чтобы показать «последнее положение» (например, на главной), сейчас нужен весь `/location` (1389 объектов). Предложение: `limit`/`last=1` либо член верхнего уровня `latest: Waypoint`.
16. **Суммарное расстояние.** `dist_total_m` не монотонен; для плитки «пройдено» нужен надёжный показатель. Предложение: `traverse_length_m` в ответе `/traverse` (сумма `length_m`) либо считать на клиенте.
17. **Согласованность образца.** В макетах `photos.html`/`manifest.html` у Curiosity `max_sol` 5066, а реальные стоянки доходят до 5073 (источник положения может быть свежее нашей синхронизации снимков); на карте использован сол 5073. Проверить на реальных данных.

**Состояния** (переключатель «Mockup», по каждой секции отдельно, есть пресет «Mixed»): загрузка (скелетон), «not loaded yet» (`items: []`, `updated_at: null`), ошибка в формате v2 с «Try again». Отставание подсвечено текстом цвета `--warn`, не только цветом.

**Данные зашиты в макет, к API не подключено.** Образцы — по 30 строкам из `samples.html`. Радиация — сгенерированная кривая (E около 160–225 мкГр/сут, B на 4 % выше, всплески выдуманы), `source_max_sol` 4843, отставание 239 солов выдумано по датам. Погода — суточные значения настоящие (см. «Погода по солам»), почасовые сгенерированы.

### Решения
- Название раздела «Data» (решение владельца 2026-11-23; было «Science»).
- Аккордеон, а не вкладки: наборы разной формы, ссылка на одну секцию через хеш, на телефоне нет горизонтальной прокрутки вкладок.
- Шкала радиации от нуля (по просьбе владельца), поэтому годовой ход (±15 %) виден слабо: это честно. Если нужно разглядеть, в полном виде — переключатель «zoom to data».
- Только поглощённая доза в мкГр/сут, без зивертов и без слов «опасно/безопасно» (в данных эквивалентной дозы нет).
- Отставание данных показано в карточке-сводке и в строке под заголовком секции (видно и у свёрнутой секции), а на графике — серой зоной.
- `credit` и `source` всегда текстом в карточке-сводке; для радиации `credit` берётся из ответа API.
- Полный вид радиации не нарисован; кнопка «Open full view» у неё неактивна (`aria-disabled`). У погоды кнопки нет: секция и есть полный вид (суточный график, инспектор, таблица).

### Ответы владельца (2026-11-23, «как рекомендовано, кроме названия»)
1. Название — **«Data»** (не «Science»).
2. Ingenuity в раздел не входит; допустима ссылка-плитка на `flights.html`.
3. Погода: в карточке суточное среднее, в полном виде — min/max и день/ночь.
4. Curiosity REMS в погоде — был отложен; решением по этапу 17 (2026-11-23) вошёл в секцию вместе с Perseverance.
5. Полного вида радиации в первой версии нет: секция, ссылка на архив.
6. Дополнительный ряд радиации — **берём скорость счёта заряженных частиц в детекторе B** (подпись «сырая скорость счёта, событий/с»); нейтральные события — после чтения документации RAD.
7. Вкладка «Samples» внутри Perseverance остаётся.
8. Секции без данных показывают «not loaded yet»; секция скрыта, только пока для неё нет ручки API.

### Что нужно от API
- `GET /api/v2/rovers/curiosity/radiation` — как в черновике `docs/proposals/stage-21-rad.md`, раздел 4: `items[].sol, earth_date, dose_e_ugy_day.mean, dose_b_ugy_day.mean, coverage`, шапка `credit`, `source_url`, `updated_at`, `source_max_sol`, `source_release`. Хватает для карточки, графика и таблицы. Один запрос без параметров (~5000 элементов) для карточки избыточен, но кешируется; если станет тяжело — параметры `sol_min`/`sol_max` уже есть.
- Для строки «Newest sol … N sols behind» нужен текущий `Rover.max_sol` Curiosity (есть в `GET /rovers/curiosity`).
- **Погода:** контракт — `docs/proposals/stage-17-weather.md`, раздел 4 (`/weather` и `/weather/{sol}`); что нужно сверх него, см. «Погода по солам → Что нужно от API».
- Общий признак «отставания»: во всех наборах полезны `source_max_sol` и `updated_at` на уровне ответа; для образцов есть `source_updated_at` и `updated_at`, но нет «последнего сола» (считаем на клиенте).
- Возможная общая ручка-оглавление `GET /api/v2/data` (какие наборы есть, у каких марсоходов, охват в солах, `updated_at`): позволит рисовать секции и «not loaded yet» одним запросом и скрывать недоступные. Без неё клиент знает набор секций заранее (рекомендую начать без неё).

### Погода по солам (этап 17, 2026-11-23)

Экран: секция «Weather by sol» в `mockups/data.html` (`#weather`). Контракт — `docs/proposals/stage-17-weather.md`, раздел 4 (`WeatherSol`, `GET /rovers/{rover}/weather`, `GET /rovers/{rover}/weather/{sol}`).

**Что на экране** (сверху вниз):
1. Переключатель марсохода Perseverance (MEDA) / Curiosity (REMS) (`radiogroup`, остаётся видимым и в состояниях «loading / not loaded yet / error»).
2. Карточка-сводка: что это, охват в солах, дата обновления, «Newest sol … N sols behind» (`Rover.max_sol` минус `source_max_sol`), `Source` и `Credit` текстом.
3. Выбор параметра (чипы с `aria-pressed`) строится из шапки `parameters` ответа: Air temp, Pressure, Humidity (бейдж «preliminary» по `quality`), Wind только у Perseverance, Ground temp и UV только у Curiosity. Ветра у Curiosity нет нигде. Рядом выбор диапазона «Sols shown» (весь марсоход / последние 365 / последние 100 / только загруженные).
4. Суточный график (SVG, без библиотек): полоса min–max (у ветра вместо неё пунктир порыва `gust_ms`, у УФ полоса от 0 до `max`), сплошная линия среднего, ось X — сол. Серая зона «not published yet» от `source_max_sol` до `max_sol`. Солы с `partial_coverage`: серые полупрозрачные столбики вместо розовой полосы, пунктир и пустые кружки на линии среднего (среднее не скрыто). Метки аномалий в полосе над графиком: ромб (`humidity_over_100`) и крест (`out_of_range`); показываются только на графике того параметра, к которому относится флаг. На графике влажности шкала поднимается выше 100 %, проведена пунктирная линия «100 %: above it is impossible». Подсказка при наведении мышью словами (сол, дата, значения, флаги с объяснением); щелчок по графику выбирает сол для инспектора. С пальца и клавиатуры тот же путь даёт ползунок инспектора.
5. Инспектор сола: ползунок (стрелки — на следующий загруженный сол), кнопки «Previous / Next anomaly» (прыжок к солам с `humidity_over_100` или `out_of_range`), строка значений выбранного параметра, полоска «Hours with air-temperature readings» (24 ячейки по `hours[].coverage`), список флагов (плашка + объяснение словами), мини-графики по часам LMST 0–23 для каждого параметра марсохода (свои шкалы, разрыв линии на `null`, у влажности «preliminary» и линия 100 %).
6. Таблица последних 8 солов: дата, средние (и min…max у температуры воздуха, порыв у ветра), часы, плашки флагов. Значение `null` пишется словом (датчик есть, данных за сол нет). Ниже 680 px строки превращаются в карточки «подпись: значение», горизонтальной прокрутки нет.

**Состояния.** Общие (панель «Mockup»): «All loading», «All not loaded yet» (текст про `items: []`, `updated_at: null`, `source_max_sol: null`), «All error» (формат ошибки v2, «Try again»). Для инспектора отдельная группа кнопок «Weather inspector»: «Sol loaded», «Loading» (скелетон), «Sol without data» (404 `sol_not_found`, текст «No data for sol N»), «Error» (503 с повтором). Параметр без значений в выбранном диапазоне (ветер Perseverance за последние 365 солов) — сообщение вместо графика, без падения. Проверено: 360 px без горизонтальной прокрутки, светлая и тёмная тема, скрипт без ошибок, внешних запросов нет.

**Данные зашиты в макет, к API не подключено.** Настоящие: суточные значения из `docs/reports/stage-17-meda-daily.csv` (Perseverance: каждый 4-й сол из 1754 плюс солы вокруг аномалий, всего 479; К переведены в °C; влажность среднее — `rh_hmean`, температура/давление — часовые средние, как в контракте) и `stage-17-rems-daily-sols1-71.csv` (Curiosity: все 64 загруженных сола 1, 9–71; солов 2–8 нет в источнике). `source_max_sol`: 1859 и 71. **Выдуманы:** все почасовые значения (генерируются по настоящим суточным min/max/mean: суточный ход, пропуски часов по `hours_covered`); влажность выше 100 % на солах 1228, 1229, 1241, 1852, 1853 (сами солы настоящие по инвентаризации, но в прототипном CSV максимум обрезан, значения 101,8–107,1 взяты для примера) и `count` во всех флагах; `out_of_range` на соле 950 (влажность, Perseverance) и на соле 30 (грунт Curiosity, из AC-5); минимум влажности Curiosity (в CSV его нет, взят 0); `earth_date` (посчитана от даты посадки, не из метки); `ls` у Perseverance настоящая (`ls_start`), у Curiosity `null`; `credit` и `source_url` Curiosity (формулировка и адрес ждут метки коллекции); дата обновления. Отличия от живого ответа: в живом ответе будут все солы (не каждый 4-й), у Curiosity ~4700 солов вместо 64 (в макете серая зона занимает почти весь график при «Whole mission», по умолчанию у Curiosity стоит «Loaded data only»), `hours` приходят из `/weather/{sol}` отдельным запросом.

**Решения для frontend-dev**
- Один запрос `/rovers/{rover}/weather` на марсоход (кэшировать по ключу марсохода); `/weather/{sol}` — при выборе сола, плюс состояния loading / 404 / ошибка в инспекторе отдельно от графика.
- Набор параметров и пометки качества брать из `parameters`, не зашивать по имени марсохода: так 17G (грунт Perseverance, `estimate`) появится без правки интерфейса. Для `estimate` нужен свой бейдж («estimate»), сейчас рисуется только «preliminary».
- Ключа `wind` у Curiosity нет, `wind: null` у Perseverance вне солов 36–313: «нет датчика» и «нет данных» различать.
- Ломать линию на пропусках: сол без строки или параметр `null` — разрыв, не интерполяция. Порог разрыва в макете `2,1 × шаг выборки`; на реальных данных (шаг 1 сол) разрыв при пропуске больше одного сола.
- `partial_coverage` рисовать иначе, а не скрывать (решение владельца 2); незнакомый код флага показывать нейтральной плашкой с кодом (контракт: список кодов растёт).
- Выбор сола: щелчок по графику, ползунок (клавиатура и палец), кнопки «Previous / Next anomaly». У ползунка задавать `aria-valuetext` (сол и флаги). Подсказка при наведении только для мыши; на касание не показывать.
- Серая зона и строка «N sols behind» считаются как у радиации: `source_max_sol` против `Rover.max_sol`.
- 4700 солов в SVG: полоса одним `path`, не по элементу на сол; на 360 px ось X — 3 подписи.

**Что нужно от API (сверх раздела 4 спецификации)**
- Для строки отставания и серой зоны нужен `Rover.max_sol` (есть в `GET /rovers/{rover}`) — один дополнительный запрос; удобнее было бы поле `rover_max_sol` в шапке погоды (необязательно).
- `earth_date` в макете приблизительна: нужна из ответа (спецификация её даёт).
- У `humidity_pct` в `WeatherSol` min у Curiosity: в прототипе CSV для REMS нет min влажности; если ручка его не даст, объект `humidity_pct` у Curiosity должен быть `{max, mean}` (как `uv_wm2`), и макет нарисует линию без полосы. Уточнить у data-engineer.
- Флаги `out_of_range` хорошо бы подписывать `parameter` ключом ответа (как в спецификации): макет по нему ставит метку на график нужного параметра. Для `wind` и `uv_wm2` ключи `parameter` совпадают с ключами сола.
- Шапка `parameters` у ветра без `min/max`: макет рисует `speed_mean_ms` как среднее и `gust_ms` как верхний пунктир; если нужна полоса «min–max» скорости, поля нет (не просим, достаточно порыва).
- Подпись источника Curiosity: `credit`/`source_url` по метке `msl_rems` (макет подставил текст-заглушку).

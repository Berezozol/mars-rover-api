# Дизайн: первые наброски фронтенда

Статичные макеты в `design/mockups/`, открываются двойным щелчком или через локальный HTTP-сервер (ссылки относительные). Фронтенд работает только на API v2 (`docs/API.md`). Название — **Sol Index** (утверждено; нейтральное, без знаков NASA/JPL; в подвале — оговорка «неофициальный проект»).

## Решения владельца (2026-11-17)

1. Название **Sol Index** утверждено.
2. Марсоход без данных (`max_sol = null`) в UI скрыт: карточки на главной, вкладки и списки марсоходов на всех экранах, быстрый переход. Сейчас скрыты Spirit и Opportunity — появятся после импорта архива. Состояние карточки «Archive import pending» убрано; на главной одна строка-подсказка «More rovers appear when their archives are imported».
3. Открытие марсохода ведёт на его последний сол — браузер снимков на `max_sol`. Туда ведут главная кнопка карточки, вкладки и пункт «Photos» в шапке; хроника — вторичная ссылка.

## Экраны

- `index.html` — главная: быстрый переход «марсоход + сол», карточки марсоходов из `GET /rovers` (только с данными: Perseverance, Curiosity) + подсказка про будущие архивы, полоса «последнее от Perseverance» из `/photos/latest`, блок для разработчиков (v1 → смена хоста, v2).
- `photos.html` — браузер снимков одного марсохода: сол или земная дата, камеры, sample_type, сетка, пагинация, состояния (переключатель «Mockup» сверху: данные / загрузка / пустой сол / 422). Без `sol` открывается последний сол марсохода. Данные: Perseverance sol 2031 (52 снимка, это и есть последний) и `?rover=curiosity` — снимки Curiosity sol 1000 (856, только `full`) вместо последнего сола 5066 (оговорено в полосе «Mockup»).
- `photo.html` — карточка снимка (PhotoDetail 81234, SUPERCAM_RMI): большой кадр, переключатель размера, метаданные, подпись, credit, источник, «новее/старее» в пределах сола, лента кадров той же камеры, `extra` под катом. Кнопка «Curiosity variant» показывает случай «есть только full».
- `manifest.html` — хроника миссии из `/manifest`: тепловая полоса всей миссии (клетка = 10 солов) + столбики по солам в диапазоне `from_sol`/`to_sol`, клик по столбику → браузер на этом соле; табличный вид для доступности.
- `map.html` — карта маршрута (этап 11; `?rover=perseverance|curiosity|spirit`, `from_sol`, `to_sol`): линия маршрута из `/traverse`, стоянки из `/location` точками, последняя стоянка выделена (ромб с подписью), подсветка диапазона солов (поля «From sol» / «To sol», пресет «Last 100 sols»), подсказка при наведении и фокусе (sol, site/drive, координаты, проезд, всего), выбор стоянки → панель «Selected stop» с кнопкой «Browse sol N photos» (`photos.html?rover=…&sol=N`), список стоянок с пагинацией (по 8, новые сверху — доступная замена карте). Состояния («Mockup» сверху): данные, загрузка, диапазон без стоянок, ошибка сервера (503 `db_unavailable`), «нет данных» (Spirit: `available: false`). Данные — урезанные реальные из `data/locations/` (Perseverance: 708 стоянок и 555 отрезков до сола 2022; Curiosity: 1389 стоянок и 1317 отрезков до сола 5073, у отрезков sol `null`), траектория упрощена (Дуглас–Пекер, допуск ~1,5–2,5 м); данные встроены в файл (~340 КБ).
- В `photo.html` добавлен блок «Location» (`PhotoDetail.location`): мини-карта (весь маршрут Perseverance + точка), бейдж Exact / Approximate, координаты, высота, стоянка (sol/site/drive), ссылка на карту. Переключатель «Mockup · location»: `exact: false` (по умолчанию), `exact: true`, `location: null` (блок скрыт целиком, без пустого заголовка). Site/drive снимка в макете заменены с 112/1874 на 93/412: стоянок site 112 в данных нет (маршрут кончается солом 2022), так что по контракту `location` для него был бы `null`.
- Во всех шапках и на карточках марсоходов главной добавлена ссылка «Route map».
- `styles.css` — токены (цвета светлой/тёмной темы, `--map-*` для карты, шрифты системные, шаг отступов 4 px), общие компоненты, заглушки снимков на CSS-градиентах.

## Ключевые решения

- Навигация: Rovers → Photos (последний сол) → Photo; Timeline — второй вход в сол; везде хлебные крошки и вкладки марсоходов (только с данными).
- Порядок карточек на главной — активные первыми (API сортирует по `id`, переупорядочиваем на клиенте).
- Марсоходы с `max_sol = null` фильтруются на клиенте и нигде не показываются (решение владельца 2).
- Сол и земная дата — переключатель «Find by: Sol | Earth date»: активно только одно поле, поэтому 422 «оба сразу» из UI не достижимо.
- «Latest sol» = `sol=max_sol` из Rover через обычный `/photos`, а не `/photos/latest` — так работают все фильтры (у `/latest` нет `sample_type`).
- Камеры — чипы: сверху камеры, снимавшие в этот сол (из `manifest.sols[].cameras`), остальные — под катом и приглушены; на чипе — `total_photos` из `/cameras` с пометкой «по всем солам».
- sample_type — сегменты All / Full / Subframe / Downsampled; прочие значения источника (`mixed`, `chemcam prc`) видны бейджем другого цвета на карточке, но в фильтре их нет (как в контракте).
- Сетка 2/3/4/6 колонок, `per_page` = 24/48/96 (делится на все варианты колонок; в пределах 1–100). Миниатюра в сетке всегда 4:3 с обрезкой, полный кадр — на странице снимка.
- Миниатюра: `images.small` → `medium` → `full`; у Curiosity грузится `full` (лениво).
- Credit — на каждой плитке сетки, под большим кадром и в метаданных.
- Под результатами — строка «API: GET …» с текущим запросом: аудитория — в том числе разработчики.
- Ошибка 422 — человеческий текст по полю из `details` + код и сырой ответ под катом; кнопка «к последнему солу».
- Пустой сол — объяснение и шаги «соседний сол» / «открыть хронику».
- Хроника: один цвет (последовательная шкала 4 ступени по квартилям + «нет снимков»), подсказка при наведении и фокусе, табличный вид; некорректный диапазон (`from > to`) — сообщение до запроса.
- Тема: светлая/тёмная по `prefers-color-scheme` + ручной переключатель в шапке; контраст текста ≥ AA, видимый фокус, подписи у полей, `role="img"`+`aria-label` у заглушек.

## Карта маршрута: решения (этап 11)

- Подложки нет: SVG на плоском фоне `--map-bg`, сетка широта/долгота с подписями (шаг подбирается по масштабу), масштабная линейка, стрелка севера. Ни одного внешнего запроса и ассета; макет полностью рабочий без подложки.
- Проекция — равнопромежуточная с поправкой cos(широты): на масштабе кратера искажения незаметны; 1° широты = 59,16 км (R = 3389,5 км) для линейки.
- Маршрут — одна фоновая линия + поверх неё подсвеченная часть диапазона; стоянки — точки (круглые концы нулевых отрезков, один `<path>`, быстро и для 1400 точек). Различие не только цветом: ромб «последняя», кольцо «выбрана», толщина линии.
- Подсветка диапазона: у Perseverance — по `properties.sol` отрезков; у Curiosity sol на отрезках `null`, поэтому крайние стоянки диапазона привязываются к ближайшим вершинам маршрута и подсвечивается участок между ними. Это приближение, на экране есть жёлтая пометка. Точнее — см. предложение 12.
- Стоянка — конец проезда: в панели оговорено, что фото этого сола могли сниматься и на других стоянках.
- Клик — выбор, не переход: на тач-экране нет hover, а прямой переход мешал бы смотреть подробности. Переход — кнопкой в панели. С клавиатуры: фокус на карту, ←/→ шагают по стоянкам диапазона, Home/End — первая/последняя, +/− масштаб, Esc снять выбор. Все стоянки также доступны списком (таблицей) справа — это неграфическая альтернатива карте.
- Масштаб колёсиком только с Ctrl/⌘ (не перехватывает прокрутку страницы); перетаскивание — мышью; на касании — кнопки ± и список (однопальцевое перетаскивание отдано прокрутке страницы).
- Диапазон валидируется до запроса (`from_sol > to_sol` — 422 в контракте). Диапазон без стоянок (например, у Perseverance солы 2010–2021 между двумя стоянками) — не ошибка, а пояснение поверх карты и кнопка «Clear range».
- Плашка «Position data ends at sol 2022. Photos reach sol 2031»: источник обновляется нерегулярно, `source_max_sol` < `max_sol` — норма, а не сбой.
- «Distance (source)» — `dist_total_m` последней стоянки с пометкой источника: по контракту оно не обязано расти от стоянки к стоянке.
- Ingenuity: вкладка «Ingenuity flights · Soon» у Perseverance, неактивна (`aria-disabled`, никуда не ведёт). Экрана нет и данных в API нет; когда появятся — вкладка включается, дизайн отдельно.
- Spirit и Opportunity на вкладках скрыты (решение владельца 2), но прямая ссылка `map.html?rover=spirit` показывает состояние «No location data» (`available: false`); когда архивы будут импортированы и вкладки появятся, оно уже готово.
- Мини-карта в карточке снимка: весь маршрут без зума + точка; при `exact: false` вокруг точки пунктирный круг (условный порядок длины одного проезда) и текст «taken while driving after the stop …»; при `location: null` блока нет совсем.

### Варианты подложки (нужно решение владельца)

1. **Без подложки** (сейчас). Плюсы: ноль зависимостей и прав, быстро, офлайн, нейтрально по «неофициальности». Минусы: нет рельефа и ориентиров, карта — «схема».
2. **Свои предрендеренные тайлы из публичных орбитальных мозаик** (например, CTX/HiRISE-мозаики кратеров Езеро и Гейла) — статический набор тайлов или один файл PMTiles рядом с фронтендом, только для двух районов (порядка десятков МБ). Плюсы: нет внешних запросов, работает за Tailscale Funnel, выглядит лучше. Минусы: нужно проверить лицензии и формулировки авторства каждой мозаики, отдельная работа по подготовке (data-engineer), размер репозитория/образа, районы маршрута со временем расширяются (Curiosity уходит дальше по склону горы Шарп).
3. **Готовый тайловый сервис** (в т.ч. тайлы JPL/MMGIS, Trek, OpenPlanetary). Плюсы: минимум работы, весь Марс. Минусы: запросы из браузера пользователя уходят третьей стороне (приватность), условия использования и доступность не гарантированы, CORS, зависимость от JPL в «неофициальном» проекте.

Рекомендация: вариант 1 — основной и единственный по умолчанию; после проверки лицензий добавить вариант 2 как необязательный слой «Imagery» (выключатель, по умолчанию выключен) только для Езеро и Гейла. Вариант 3 не брать. Структура готова: подложка — отдельная группа под маршрутом в том же SVG (в пиксельных координатах с той же проекцией).

## Чего не хватает в API v2 (предложения)

1. **Соседи снимка внутри сола.** Для «новее/старее» и «N из 52» на `photo.html` фронтенду сейчас нужно выгружать весь сол. Предложение: в PhotoDetail поля `prev_id`, `next_id` (в порядке сортировки списка) и `position`/`sol_total`; опционально — с учётом фильтра `camera`.
2. **Счётчики камер за сол.** `/cameras` даёт `total_photos` только по всей миссии, а в `manifest.sols[].cameras` — только коды. Предложение: `cameras` в манифесте как `[{"code", "total_photos"}]` или параметр `sol` у `/cameras`, чтобы на чипах были числа за сол.
3. **Размеры кадра.** Нет `width`/`height` (у Perseverance лежат в `extra.dimension` строкой). Нужны для заглушек нужной пропорции, без «прыжков» сетки и для подписи размеров в переключателе. Предложение: `width`, `height` в Photo (и по размерам в `images`, если известны).
4. **Миниатюры Curiosity.** `small/medium/large` = `null`, сетка грузит полноразмерные файлы. Предложение: обсудить превью (например, свой ресайз/кеш или поле `thumbnail`, если в фиде MSL есть уменьшенные версии).
5. **Местное солнечное время (LMST).** Есть только в `extra` (`lmst`) и не для всех марсоходов. Для энтузиастов это «время на Марсе». Предложение: поле `local_time` в PhotoDetail.
6. **`sample_type` у `/photos/latest`.** Нет фильтра, в отличие от `/photos`. Предложение: добавить для единообразия (пока обходим через `sol=max_sol`).
7. **Дата → сол.** При поиске по `earth_date` с пустым результатом нельзя подсказать ближайший сол со снимками без загрузки манифеста. Предложение: в ответе списка при пустом результате — `nearest_sols: {"before": 2028, "after": 2030}`, либо полагаться на манифест (тогда зафиксировать это как сценарий).
8. **Лёгкий манифест.** У Curiosity >5000 солов, в каждом — массив камер; для тепловой полосы камеры не нужны. Предложение: `?fields=sol,total_photos` или агрегат `?bucket=10`.
9. **Конец миссии.** Для завершённых миссий нет `end_date`/даты последнего контакта, показываем `max_date` как «Last date». Предложение: `end_date` в Rover.
10. **Происхождение данных.** Для Spirit/Opportunity `last_synced_at` — это время разового импорта; полезно различать: `data_source: "sync" | "archive_import"` или отдельное `imported_at`.
11. **CORS.** В контракте не описан; фронтенд на отдельном домене не сможет ходить в API. Нужно решение (разрешённые origin или фронтенд на том же хосте).

12. **Связь отрезков маршрута со стоянками.** У Curiosity `properties.sol` всегда `null`, и подсветка диапазона солов приближённая. Предложение: в `properties` отрезка — `from`/`to` как `{site, drive}` (у Perseverance источник даёт `fromRMC`/`toRMC`; для Curiosity можно вывести по порядку) либо вычислять `sol` для Curiosity на бэкенде по ближайшим стоянкам.
13. **Фильтр фото по стоянке.** «Фото, снятые на этой стоянке» требуют `site`/`drive` в `/photos` (сейчас фильтры — `sol`, `camera`, `sample_type`, дата). Предложение: `site` и `drive` (или `drive_from`/`drive_to`). Пока карта ведёт на весь сол.
14. **Размер ответа.** `/traverse` отдаётся целиком: исходные файлы 1,7 МБ (Perseverance) и 1,4 МБ (Curiosity), 36 тыс. и 27 тыс. вершин; для карты хватает ~4 тыс. Предложение: gzip (обязательно) и необязательный параметр `simplify` (допуск, м) либо уровни детализации.
15. **Последняя стоянка без полного списка.** Чтобы показать «последнее положение» (например, на главной), сейчас нужен весь `/location` (1389 объектов). Предложение: `limit`/`last=1` либо член верхнего уровня `latest: Waypoint`.
16. **Суммарное расстояние.** `dist_total_m` не монотонен; для плитки «пройдено» нужен надёжный показатель. Предложение: `traverse_length_m` в ответе `/traverse` (сумма `length_m`) либо считать на клиенте.
17. **Согласованность образца.** В макетах `photos.html`/`manifest.html` у Curiosity `max_sol` 5066, а реальные стоянки доходят до 5073 (источник положения может быть свежее нашей синхронизации снимков); на карте использован сол 5073. Проверить на реальных данных.

## Открытые вопросы владельцу

1. Формат `details` для неизвестной камеры: в общих правилах — список `{"field","message"}`, у `/photos` — «список допустимых кодов». Это коды внутри `message` или отдельная структура? От этого зависит подсказка «доступные камеры» в UI.
2. Солы без снимков в `manifest.sols` отсутствуют или приходят с `total_photos: 0`? (Макет считает, что отсутствуют.)
3. Открывать изображения напрямую по `images.*` (URL NASA) или через `/api/v2/photos/{id}/image?size=` (редирект + кеш)? Второе удобнее для «Open image» и скачивания, первое — для сетки.
4. Ссылка «View on the mission’s raw-image page» ведёт на сайт NASA — допустимо ли с точки зрения «неофициальности» (без логотипов, только текстовая ссылка)?
5. Язык интерфейса — только английский или позже добавить русский?
6. Нужен ли «ночной» режим просмотра (тёмный фон кадра всегда, как сейчас на странице снимка) и полноэкранный просмотр?

7. Подложка карты: вариант 1, 2 или 3 (см. «Варианты подложки»; рекомендация — 1, затем 2 после проверки лицензий)?
8. Клик по стоянке: выбор + кнопка «Browse photos» (как в макете) или сразу переход в браузер снимков на соле?
9. «Route map» — отдельный пункт главной навигации (как в макете) или только вкладка внутри марсохода?
10. Единицы: км/м (как сейчас) или переключатель км/мили (в данных источника есть `dist_mi`, в нашем API нет)?

## Как смотреть

Открыть `design/mockups/index.html` двойным щелчком или `http://127.0.0.1:8811/index.html` (сервер раздаёт `design/mockups`); остальные экраны — по ссылкам в шапке. Варианты: `photos.html?rover=curiosity`, `manifest.html?rover=curiosity`, `map.html?rover=curiosity`, `map.html?rover=perseverance&from_sol=1900&to_sol=2022` (диапазон), `map.html?rover=spirit` (нет данных). Блок «Location» в `photo.html` переключается кнопками «Mockup · location». Переключатели с пометкой «Mockup» — только для показа состояний, в продукт не входят.

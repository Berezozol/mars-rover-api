Ты тимлид. Проверь UI так, как его увидит пользователь. Аргументы: $ARGUMENTS (если пусто — экраны, затронутые `git diff --stat -- frontend design`).

## 1. Запуск
- API: `mcp__Claude_Browser__preview_start` с `name: "api-local"` (порт 8000, `SYNC_ENABLED=false`; нужна база: `docker compose up -d db`). Если фронтенд собран (`npm run build` в `frontend/`), сервер раздаёт его на `/`; иначе `frontend-local` (порт 5174, прокси на 8000). `frontend-public` (порт 5173, данные публичного сервера) — только если я просил.
- Макеты `design/mockups/*.html` открывай по HTTP (`python -m http.server` в `design/mockups`), не по `file://`: встроенный браузер показывает `file://` как снимок без скриптов. Макеты статичны — явно скажи, что к API они не подключены.

## 2. Проверка (на каждом экране)
- `read_console_messages` — ошибки и предупреждения; `read_network_requests` — падения, 4xx/5xx, неожиданные внешние запросы.
- Состояния: данные, загрузка, пусто (пустой сол), `404`, `422`, `503`. Если нечем вызвать — перечисли, что не проверено.
- `resize_window` с `preset: mobile` (375×812) — нет горизонтальной прокрутки, плитки не прыгают; затем `colorScheme: dark`; в конце `preset: desktop`.
- Правила проекта: `credit` у каждого снимка, нет логотипов NASA/JPL и слов об одобрении, у кнопок и ссылок понятные имена (`read_page`, `find`), нет вложенных областей прокрутки, перехватывающих колесо.
- Клавиатура: Tab проходит основные действия, фокус виден.

## 3. Отчёт
Таблица «экран → что проверено → результат», ошибки консоли дословно, скриншоты ключевых состояний (по одному на экран, не больше 6), список не проверенного. Исправление не делай сам: дефекты — `frontend-dev` (`frontend/`) или `designer` (`design/`), с шагами воспроизведения. Закончив, верни окно в `desktop` и останови серверы, которые запускал.

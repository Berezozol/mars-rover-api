Ты — тимлид, обновляешь записанные ответы источников, на которых работают тесты (тесты сами в сеть не ходят). Часть: $ARGUMENTS (по умолчанию спроси меня). Скрипт — зона `qa-engineer`: если его нужно менять (новый источник, новая часть), поручи это ему, а не правь сам.

## 1. Что делает часть — без сети
Прочитай docstring `scripts/record_fixtures.py` и функцию нужной части:
- `mer`, `mmgis` — без сети, копируют подготовленные `data-engineer` файлы из `data/`;
- `base`, `m2020-range`, `all` — живые GET к фидам JPL;
- `mer-img` — скачивает до шести `.img` из PDS (крупные файлы, в репозиторий попадают только маленькие).
Посчитай точное число запросов и к каким хостам.

## 2. Запросы — и стоп
Для сетевых частей покажи мне: хосты, число запросов, примерный объём. **Жди «ок».** Офлайн-части (`mer`, `mmgis`) запускай сразу.

## 3. Запись
`uv run python scripts/record_fixtures.py --part <part>`; полные ответы для анализа — только вне репозитория (`--raw-dir <scratchpad>`).

## 4. Проверка результата
- `git status tests/fixtures` и `git diff --stat tests/fixtures`: изменились только ожидаемые файлы.
- Обрезка: в JSON-фикстурах 3–5 элементов на ответ, файлы небольшие (крупнее ~200 КБ — вопрос).
- Нет секретов и персональных данных: поиск `api_key`, `token`, `key=`, `Authorization` в изменённых файлах.
- Синтетические фикстуры с причудами (`"UNK"`, числа-строки, `null`) на месте, их скрипт не перезаписал.
- `uv run pytest -q -m unit` — адаптеры работают на новых фикстурах. Упавшие тесты не ослабляй: если источник изменился, это находка для `data-engineer` (запись в `docs/DATA-SOURCES.md`) и `backend-dev` (адаптер).

## 5. Итог
Какие файлы обновлены, сколько запросов сделано, что нового в ответах источника по сравнению со старыми фикстурами.

Ты составляешь сообщение коммита. Контекст: $ARGUMENTS. Коммит и пуш — только после моего «ок» (`CLAUDE.md`).

## 1. Что входит в коммит
- `git status` и `git diff --stat` (и `git diff --cached --stat`).
- В папке могут работать другие сессии: отбери только файлы этой работы. Чужие и непонятные изменения перечисли отдельно и в коммит не включай.
- Проверь, что в изменениях нет `.env`, логов (`.backfill-*.log`, `setup-log.txt`), `data/`, `frontend/dist`, `node_modules`.

## 2. Формат (по истории `git log`)
```
<Глагол в повелительном наклонении> <что сделано> (stage <N>)

- <изменение API или поведения: ручки, параметры, миграция NNNN>
- <загрузка, синхронизация, источники>
- Sol Index: <изменения фронтенда>
- Docs: <какие документы>

Co-Authored-By: <строка соавторства из текущих правил сессии>
```
- Заголовок на английском, до ~72 символов, без точки; `(stage N)` — если коммит закрывает этап или его часть.
- Тело: пункты по смыслу, а не по файлам; строки до ~72 символов; ручки и команды — в обратных кавычках.
- Небольшой коммит — заголовок и одна-две строки пояснения, без списка.

## 3. Показать — и стоп
Покажи сообщение и точный список файлов. **Жди «ок».** После «ок»: `git add <файлы по одному>` (не `git add .`/`-A`), `git commit` с сообщением через here-string, затем `git log --oneline -1`. Не пушь без отдельного «ок».

Ты тимлид. Выкладываешь на продакшен (Contabo VPS, `/srv/mars`, проект `mars`, Caddy + приложение + Postgres). Это ручной путь: в обычной работе выкладку делает конвейер после слияния PR. Любые действия на сервере, меняющие состояние, — только после моего «ок».

## 1. Проверки — без изменений
- Выкладывается только то, что слито в `master`: `git fetch`, `git log origin/master --oneline -5`. Незакоммиченное и несмерженное не выкладывается.
- Что изменилось с прошлой выкладки: тег работающего образа — `ssh deploy@<VPS_IP> 'grep ^APP_TAG= /srv/mars/.env'` (адрес сервера — из моих заметок, в репозитории его нет; в отчёт целиком не пиши), затем `git log --oneline <тег>..origin/master`.
- Новые миграции: `git diff --stat <тег>..origin/master -- migrations/`; для каждой прочитай `downgrade` и оцени, обратно ли совместима со старым приложением. Опасные (удаление, переименование) — отдельно мне.
- CI на этом коммите зелёный: `gh run list --branch master --limit 3`.
- SSH работает без пароля: `ssh -o BatchMode=yes deploy@<VPS_IP> 'echo ok'`. На Windows используй `C:\Windows\System32\OpenSSH\ssh.exe` (ключ в ssh-agent).

## 2. План — и стоп
Покажи мне: какой коммит выкладывается, список изменений по одной строке, миграции (и безопасны ли), что увидят клиенты (v1, v2, фронтенд), риски, как откатить. **Жди «ок».**

## 3. Выкладка
- По SSH на сервере: `/srv/mars/repo/deploy/vps/update.sh` (с `--skip-pull`, если передан такой аргумент). Скрипт делает: pull, сборку образа, бэкап, миграции, пересоздание `app`, проверку `/health`.
- Запоминай прошлый `APP_TAG` до запуска: он нужен для отката.
- Если скрипт упал, ничего не откатывай сам: покажи шаг, на котором упало, и `docker compose logs --tail 200 app` (из `/srv/mars`), предложи действия и жди «ок».

## 4. Проверка
- С этого ПК: `uv run python deploy/smoke.py https://api.solindex.net` — все проверки проходят (17 запросов).
- На сервере: `curl -s http://127.0.0.1:8000/health` → `200`, `docker compose ps` → контейнеры healthy, `/health/sync` → `200`.
- После миграции, добавившей индексы под запросы на `photos`: `VACUUM (ANALYZE) photos` по указанию в записи этапа.

## 5. Откат (только после моего «ок»)
`sed -i 's/^APP_TAG=.*/APP_TAG=<прошлый тег>/' /srv/mars/.env && cd /srv/mars && docker compose up -d app`. Если миграции были необратимо несовместимы со старым приложением — восстановление из бэкапа (`/srv/mars/repo/deploy/vps/restore.sh`, README, «Backups and restore»), только по моему решению.

## 6. Итог
Коммит на продакшене, результат `smoke.py` и `/health`, путь к свежему бэкапу, что проверить мне руками (одна-две вещи), и если конвейер не сработал, почему (чтобы его починить).

Ты — тимлид, выкатываешь новую версию на продакшен (ноутбук владельца, compose в `%USERPROFILE%\mars-server`, проект `mars`, наружу через Tailscale Funnel). Подробности — `deploy/README.md`. Аргументы: $ARGUMENTS (`--skip-pull` — собрать то, что сейчас в рабочей копии, без `git pull`).

## 1. Проверки — без изменений
- `git status` и `git log --oneline -5`: выкатывается только закоммиченное. Если есть незакоммиченные изменения в `app/`, `migrations/`, `frontend/`, `Dockerfile` — остановись и скажи, что они в выкладку не попадут (или нужен коммит с моим «ок»).
- Что изменилось с прошлой выкладки: `git log --oneline <прошлый коммит>..HEAD`. Прошлый коммит — из `GET http://127.0.0.1:8000/health` (если отдаёт версию) или из последнего вывода `update.ps1`; не нашёл — спроси меня.
- Есть ли новые миграции (`git diff --stat <прошлый>..HEAD -- migrations/`); для каждой прочитай `downgrade`.
- CI на этом коммите зелёный (`gh run list --limit 3`, если `gh` доступен); иначе локально `uv run ruff check .` и `uv run pytest -q -n 12`.
- `docker version` — Docker запущен.

## 2. План — и стоп
Покажи мне: коммит, список изменений одной строкой каждое, миграции (и обратимы ли), что увидят клиенты, риски. **Жди «ок».** Это изменение продакшена.

## 3. Выкладка
`powershell -NoProfile -ExecutionPolicy Bypass -File deploy/laptop/update.ps1` (с `-SkipPull`, если передан `--skip-pull`). Сборка образа долгая: запускай с таймаутом 600000 мс. Скрипт сам делает бэкап, миграции, перезапуск и ждёт `/health`.
Если скрипт упал — ничего не откатывай сам: покажи шаг, на котором упало, и последние 200 строк `docker compose -p mars logs --tail 200 app`, предложи следующий шаг и жди решения.

## 4. Проверка
- `uv run python deploy/smoke.py http://127.0.0.1:8000`
- по публичному адресу (из памяти сессии о хостинге; в отчёт адрес не пиши целиком, если я не просил): `uv run python deploy/smoke.py https://<публичный хост>` — это запросы к нашему же сервису, они входят в «ок» шага 2.
- `GET /health/sync` — планировщик жив, последние запуски синхронизации без ошибок.

## 5. Итог
Коммит на продакшене, результат обоих smoke-тестов, путь к свежему бэкапу (из вывода `backup.ps1`), что проверить мне руками (одна-две ссылки на страницы), и строка в «Журнал этапов» `docs/PLAN.md`, если выкладка закрывает этап.

Ты — тимлид, проверяешь, что синхронизация марсохода работает и данные сходятся с источником. Аргументы: $ARGUMENTS — марсоход (`curiosity` или `perseverance`; Spirit, Opportunity и Ingenuity — архивные, для них только шаг 4 офлайн), необязательно диапазон солов.

Работаешь только с базой разработки `mars` на `localhost:5433`. Продакшен не трогаешь.

## 1. Подготовка — без сети
- `docker compose up -d db`, `uv run alembic upgrade head`.
- Диапазон: если не задан — три последних сола, которые уже есть в базе (`max_sol` из `GET /api/v2/rovers/<rover>` локального сервера или запросом к БД через `uv run python -c`).
- Посмотри последние записи `sync_runs` по марсоходу: статусы, `partial`, ошибки.

## 2. План запросов — и стоп
Скажи мне: марсоход, солы, примерное число запросов к фиду JPL (по одному на страницу сола, у Perseverance страницы по 100 снимков) и что ещё спросит сверка. **Жди «ок»** — это запросы к внешнему сайту.

## 3. Пробная синхронизация
`uv run python -m app.cli sync --rover <rover> --from-sol <A> --to-sol <B>`. Повтори ту же команду второй раз: число снимков не должно измениться (идемпотентность).

## 4. Сверка
`uv run python -m app.cli reconcile --rover <rover> --output <scratchpad>/reconcile-<rover>.json` (с `--offline`, если я не дал «ок» на запрос итогов источника). Сравни число снимков по солам и камерам с источником, найди пропуски и дубли.

## 5. Отчёт
- что загрузилось: солы, снимки, камеры, время;
- совпадение с источником, расхождения со строками отчёта сверки;
- новые причуды источника (новые поля, `null`, другие форматы, коды ответов) — если есть, не правь сам: это задача `data-engineer` (проверка и запись в `docs/DATA-SOURCES.md`) и `backend-dev` (адаптер). Запуск `data-engineer` — по правилам бюджета из `CLAUDE.md` (`/budget`).

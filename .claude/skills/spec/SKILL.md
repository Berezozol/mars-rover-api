Ты тимлид. Задача: $ARGUMENTS. Цель — чтобы разработчики и тестировщики получили однозначное задание, а я — готовое решение на «ок». Спецификация не заменяет `docs/PLAN.md`: этап и критерии готовности там, детали и AC — в спецификации.

## 1. Нужна ли полная проработка
- **Мелкая задача** (правка поведения без новой таблицы и без изменения контракта, доработка интерфейса, исправление дефекта): пиши спецификацию сам, без `architect`. Хватает разделов 0, 2 (AC), 7 и 8 шаблона.
- **Нетривиальная** (новая таблица или миграция, изменение `API.md`/`LEGACY-API.md`, новый внешний источник, развилка с несколькими вариантами): запусти `architect` с задачей «заполни `docs/proposals/_TEMPLATE.md` для <тема>», обернув запуск в `/budget before architect <тема>` и `/budget after` (лимит 5%). Передай ему путь к шаблону, этап в `docs/PLAN.md`, мои уточнения.
- Если не уверен — начни с мелкой формы и скажи мне, что нужна проработка.

## 2. Подготовка
Прочитай этап в `docs/PLAN.md`, нужные разделы `docs/API.md`, `docs/DATA-SOURCES.md`, `docs/ARCHITECTURE.md` и существующие проработки в `docs/proposals/` (не решай заново то, что уже решено). Посмотри код, на который опирается задача.

## 3. Содержание
1. Скопируй `docs/proposals/_TEMPLATE.md` в `docs/proposals/stage-<N>-<тема>.md` (или `<тема>.md` для доработки вне этапа) и заполни.
2. **Критерии приёмки** — каждый проверяемый, в форме «вход → ожидаемый результат», с номером `AC-N`, с указанием, кто и на каком слое проверяет. Критерий без возможной проверки перепиши или убери.
3. **Задания ролям** — файлы из зон по `CLAUDE.md`, общие имена функций и файлов, чтобы `backend-dev` с `qa-engineer` и `frontend-dev` с `frontend-qa` работали параллельно.
4. **Внешние запросы** — отдельным списком (хост, сколько, зачем) для моего «ок».
5. **Вопросы владельцу** — только то, что решаю я, с рекомендованным ответом.
6. Не выдумывай факты об источниках: опирайся на `DATA-SOURCES.md` и фикстуры, остальное помечай `[не проверено]`.

7. Проверь форму: `uv run --no-project python .claude/tools/spec_lint.py <файл спецификации>` — нет пропущенных разделов, AC пронумерованы по порядку и написаны как «вход → результат», не осталось заготовок из шаблона.

## 4. Покажи мне
Кратко: цель, границы, список AC, вопросы с рекомендацией, расчёт расхода токенов (по ролям — порядок величины). **Жди «ок».** После «ок» спецификация — вход для `/stage` (шаг «План») и для запуска ролей: передавай ролям номера AC и путь к файлу, они не видят наш разговор. Изменение контракта — `/contract-change`, коммит — `/commit-msg` только после моего «ок».

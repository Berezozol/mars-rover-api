## Главное
- Единственный проверенный источник — HTML-таблица на science.nasa.gov (30 строк, колонки: номер, дата и сол запечатывания, имя, объект, место отбора, текущее место, ссылка на PDF-досье, тип образца, высота, тип породы).
- Есть статус «на борту» (21) / «в депо» (9) и тип материала (27 керн, 2 реголит, 1 атмосферный). Серийных номеров трубок, координат и site/drive нет.
- Таблица отстаёт от миссии: последний образец с солом — № 28 (сол 1441, 10.03.2025); № 29 и 30 с `TBD`. Страница обновлена 2026-06-20 (по `article:modified_time`), сейчас сол ~2030. Значит, образцы после № 30 (если они были) в источнике не видны.

## Связь с положением (этап 11)
Связать можно только по солу: `Sol Sealed` ↔ `rover_waypoints.sol` (M20 waypoints: 708 стоянок, сол 13…2022, до 4 стоянок на сол, пара `(site, drive)` уникальна). Точное совпадение для сола может не найтись (стоянки не на каждый сол): брать стоянку этого сола с наибольшим `drive`, иначе последнюю с `sol <=` сол образца (`match_kind = exact|nearest_before`, и разница в солах в ответе). Снимки сола берём из `photos` по `(rover, sol)`. Для № 29, 30 (`TBD`) связи нет — `sol = null`. Связь по названию объекта (`Feature Name`) с MMGIS не проверялась: в waypoints нет имён объектов [не проверено].

## Рекомендация
1. Источник — HTML-таблица страницы (иного машиночитаемого нет). Парсер в `app/sources/samples.py` (selectolax/lxml или `html.parser`; добавление зависимости решает backend-dev), одна таблица `figure.wp-block-table table`, разбор по заголовкам колонок, не по позициям; если заголовков не 11 или не совпали с ожидаемыми — ошибка и алерт, данные не трогать.
2. Частота: раз в сутки с условным запросом (`ETag`/`Last-Modified`, если есть; на странице `cache-control: max-age=300`) — как у MMGIS; полная замена списка в транзакции (30 строк).
3. Запасной ручной путь: сид-файл `scripts/`/миграция с 30 строк на случай смены вёрстки; новые образцы добавляются командой/правкой. Владелец решает, нужна ли ручная доливка № 31+ из других публикаций.

## Эскиз модели
Таблица `rover_samples`: `id`, `rover_id` (FK, сейчас только perseverance), `number` (int, unique с rover), `name`, `feature_name`, `sampling_location`, `sample_type` (`rock_core|regolith|atmospheric`, исходная строка сохраняется), `rock_type` (текст), `status` (`on_rover|depot`, из `Current Location`; исходное значение в `extra`), `sealed_on` (date, null при `TBD`), `sol` (int, null при `TBD`), `height_cm` (numeric, null для `n/a`/оценки), `height_note` (исходная строка), `dossier_url` (PDF, может быть null), `site`/`drive` (ссылка на стоянку, null если нет), `waypoint_match` (`exact|nearest_before|null`), `source_updated_at`, `created_at`, `updated_at`.
Ручка: `/api/v2/rovers/perseverance/samples` (список), `/samples/{number}` (карточка: образец + стоянка + `photos_url` на `/photos?sol=`).

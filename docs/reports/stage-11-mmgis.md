## Расхождения с черновиком

1. Координаты трёхмерные, в черновике `[lon, lat]`: адаптер обязан отбрасывать `z` (в M20 traverse `z` местами мусорный, ~2e-5).
2. У traverse Curiosity нет `sol` — `from_sol`/`to_sol` у `/traverse` для неё не работают; ADR-1 это предусматривает (`sol = null`), но контракт нужно уточнить (у Curiosity фильтр игнорируется или все сегменты с `sol: null`; решение за архитектором/владельцем). `MultiLineString` есть (один, первый объект MSL).
3. Свойство `images` у M20 (список панорам) и `Note`, `elev_radii`, `radius` с заглушкой `-9999.0`: в `extra` их складывать не стоит (`images` раздувает строку) — предложение: `extra` не заполнять или брать белый список.
4. «Отставание ~9-10 солов» неточно: M20 файл не обновлялся с 2026-10-28 (сол 2022), реально отставание больше и нерегулярно; Curiosity отстаёт на ~4 сола. Алерт «3 дня без обновления» по `fetched_at` не сработает на «источник не меняется» — стоит смотреть и на `max_sol`/`changed_at` (на усмотрение архитектора).
5. Дубликатов `(site, drive)` нет — правило дедупликации остаётся только защитой. Типы совпали с предположениями (числа, не строки; `null` нет).
6. `dist_total_m` по порядку не монотонна; в API её нельзя представлять как накопительную без оговорок.
7. Охрана «90% строк»: проверить рост нечем (одна выборка); файлы названы `..._sol2022_all` / `..._tosol2022` — перезаписываются целиком, снижение числа объектов у источника не наблюдалось [не проверено].
8. Не проверено: сервер отвечает 304 на `If-None-Match`/`If-Modified-Since` (запрос не делался; можно использовать ETag для экономии трафика).

## Рекомендация по модели данных и загрузке (этап 17)
- Таблицы: `weather_daily(rover_id, sol, …)` — по величине `*_min/_max/_mean`, `n`, `coverage_hours`, `source_version`; `weather_hourly(rover_id, sol, lmst_hour, …)` — средние по часу (24 строки на сол, ≈ 170 тыс. строк на историю) для суточных графиков. Сырые измерения не хранить (≈ 65 ГБ).
- Величины: давление, воздух, грунт, влажность, УФ, ветер. Ветер Curiosity после сола ≈ 1485 ненадёжен [из памяти] — фильтровать по маске.
- Загрузка: CLI `weather-sync --rover X --from-sol --to-sol`; на сол — листинг, нужные файлы потоком, свёртка на лету, файлы не сохраняются; состояние по солам (md5 из метки MEDA); новые диапазоны — по корневому листингу раз в квартал. История — запусками по диапазону (≈ 90–134 сола, ≈ 3–4 мин на запросы плюс скачивание ≈ 1 ГБ), каждый < 10 минут.
- API: `data_through_sol` в ответе; солы без данных — `null`, не нули.
- Перед разработкой желательно ещё: `ANCILLARY.xml` MEDA (где воздух и ветер) и первые КБ одной реальной таблицы каждой миссии (Range-запросом) — 3–4 GET.

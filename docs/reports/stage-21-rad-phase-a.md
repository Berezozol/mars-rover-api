## Выводы, меняющие черновик спецификации (важно)

1. **`START_OBS_MARS` не даёт «сол наблюдения».** В обоих файлах сол в `START_OBS_MARS` у **всех** наблюдений равен `START_SOL` файла (4843: 176 из 176; сол 10: 26 из 26), а местное время «заворачивается»: в файле 4843 последнее наблюдение (UTC 2026-081 17:46:10, через 24 ч 28 мин после начала) помечено `"4843 0:04:39"`, хотя по местному времени это уже сол 4844. Хвоста суток в чужом файле нет: файл = интервал от своего начала до начала следующего файла (медиана шага между началами файлов 24,67 ч = сол). Значит **сол = `START_SOL` (и сол из имени файла)**, вклады `rad_file_sols` по солу из `START_OBS_MARS` не нужны; нужна только дедупликация нескольких файлов одного сола (ниже). `[не проверено]`: начало файла 4844 (не качал) — перекрытия с 4843 по времени не видно из перечня.
2. **Ранний формат (2012) другой.** В файле сола 10: нет `OBS_DURATION` и `RAD_FIRMWARE_VERSION`; `QC=00000000` без кавычек (в новом — `QC="00000000"`); `START_SOL=0010` с ведущими нулями; `SOFTWARE_VERSION=0.0`; нет секций `HISTOGRAMS`/`HISTOGRAM_NEUTRAL_*`; секция `[COUNTERS]`+`L1`+`L2` есть. Правило AC-3 «`OBS_DURATION` от 1 до 7200» отбросит **все** ранние наблюдения: длительность нужно брать из `COUNTER_L1.duration` (960 с в сол 10; в новом файле 930 при `OBS_DURATION` 961, т. е. это живое время счётчика) либо принять «нет `OBS_DURATION`» отдельным случаем.
3. **`START_OBS_UTC` бывает мусором.** В сол 10 наблюдение 12 имеет `2013-123 21:52:00` при соседях `2012-229 07:50` и `08:13` (год спустя). Это тот же класс, что «Date Range Error» в `TIMING_ERRORS.TXT`. Для `earth_date` и интервалов дедупликации брать медиану/`START_TIME` шапки, а не отдельные `START_OBS_UTC`; наблюдение с UTC вне ±2 сут от `START_TIME` не использовать для интервала.
4. **QC ≠ 0 бывает, и это правильно исключать.** В файле 4843 из 176 блоков `QC="00000001"` у 4 — это две пары (дозовое наблюдение + его PHA-близнец) у **укороченных** наблюдений: `OBS_DURATION` 272 и 579 вместо 961. Их доза занижена (B 2,06 и 4,41 мкГр/ч против соседних ≈ 6,9 и ≈ 7,4). Среди дозовых наблюдений QC≠0 у 2 из 88 (2,3 %); в раннем файле — 0 из 26. Правило «QC = 0» подтверждено, порога 5 % не превышено. Что значит бит 0 — `[догадка]` «наблюдение оборвано/неполное»; документ не читал.
5. **Число файлов: 5569, не 4850.** См. раздел «CHECKSUMS».

### Маркеры пропуска и QC
- `-1` в `COUNTER_L1.fast` — быстрый счётчик не включён (норма); `-2` — канал `N/A` (строки 0,1 и 34,35) и отсутствие данных в `PHA`; `-1` у `OBS_DURATION` в моём разборе раннего файла — это «поля нет» (ключа в файле нет, `-1` — значение по умолчанию скрипта).
- `QC`: значения `00000000` и `00000001` (только новый файл; см. выше). `ROVER_LAT/LON/ELEV/AZIMUTH/ZENITH` — нули в обоих файлах.

### Счётчики и суточный поток частиц
- L1 даёт по каждому каналу (A1/A2 — кремний, B, C, D, E, F; суффиксы `L/M/H/U`, `x1/x4/x8` — порог/усиление `[догадка]` по именам) число срабатываний за `duration` с. L2 — число событий заданной логики (например `BU` — заряженная частица в кремниевом B; `EH&EI` — совпадение в E).
- Сутки: Σ счёт / Σ `duration` — **скорость счёта в событиях/с**. Пример, файл 4843: канал `BU-x8` — 7,01 /с (сумма L2 `BU` за 88 наблюдений 565 992); `A1U` — 1,86 /с; `F1L` (антисовпадение) — 53,4 /с. Корреляция счёта `BU` на наблюдение с дозой B внутри суток — **0,89** (88 точек, один сол — не доказательство).
- Это не поток в частицах/см²/с/ср: нужен геометрический фактор и калибровка из документации прибора (в файле их нет; `DOCUMENT/` кроме `TIMING_ERRORS` я не читал).

### Гистограммы и нейтральные частицы
- Есть две: `HISTOGRAM_NEUTRAL_D` и `HISTOGRAM_NEUTRAL_E` (имена с «NEUTRAL»), 96 бинов; в L2 те же детекторы описаны логикой «D/E сработал, антисовпадение `F` и заряжённые каналы B/C молчат» (`!F1L&!BU&!C2H&!C2L&!CU&DH&DI&!F2H`) — по логике это события без заряженного трека, то есть кандидаты в нейтральные частицы (нейтроны, гамма) `[догадка по именам и логике, документ не читал]`. Значения по бинам = счёт/доля живого времени (минимальное ненулевое 1,033 = 1/0,968 при `alive` 96,809 %; проверено на наблюдении 0).
- Сумма по бинам: D — среднее 366 (29–497) на наблюдение, E — 181 (13–242); это **не** совпадает с L2-счётом (отношение 0,29–0,54, не константа), т. е. гистограмма использует иные пороги `[догадка]`.
- Энерговыделение (энергия, оставленная в детекторе), а не энергия нейтрона; получить нейтронный поток или дозу — отдельная работа с функцией отклика (своё научное вычисление).
- В раннем файле (сол 10) этих гистограмм **нет** `[проверено только на одном файле]`.
- Спектры LET (`DOSIMETRY_LET_B_A1/A2`) — спектры по линейной передаче энергии заряжённых частиц в B: основа для эквивалентной дозы, но коэффициент качества в файле **не** приведён.

### Эквивалентная доза / коэффициент качества
В файле нет ни дозы в зивертах, ни коэффициента качества, ни слов `equivalent`/`quality`. Есть только поглощённая доза (B, E) и LET-спектры. Для мЗв нужен свой расчёт (спектр LET × функция Q) — не рекомендуется.

### PHA
97 % объёма (в среднем 400–600 строк на наблюдение, до 1250 Б на строку). Для сводок не нужен, пропускаем потоком. Скорость чтения не зависит от неё: пропуск секции — только подсчёт CRLF.

### Вопрос 1. Что говорит SIS
- **QC** (раздел 4.2.1.2, 8 бит): `00000000` — проблем нет; `00000001` — «могут быть неизвестные проблемы качества»; `00000100` — RAD в режиме DAN (бит 2); `00001000` — RAD в режиме Solar Event (бит 3); старшие зарезервированы; биты складываются (`00000101`). SIS добавляет, что QC и позиция ровера «пока не реализованы, это заглушки», но в наших файлах `00000001` реально стоит у укороченных наблюдений. Биты 2 и 3 в четырёх разобранных файлах (сол 10, 1649, 1650, 4843) не встретились; в других солах `[не проверено]`. DAN — активный нейтронный источник: при бите 2 нейтральные счёты искажены.
- **COUNTER_L2** (4.2.1.3.2): колонки `entry` (номер строки меню, до 16; в файл попадают строки с ненулевой маской чтения), `count` (число событий, совпавших с логикой строки за наблюдение), `read` (сколько из них прочитано), далее маски EVIL-таблицы и логика. Строка №4 во всех файлах (2012, 2017, 2026) — логика `BU`, `count` = `read` во всех наблюдениях. SIS не называет её «заряженными частицами»: это события с медленным токеном детектора B (кремний, канал `BU-x8`). Честная подпись — «скорость счёта детектора B, событий/с»; «заряженные» — наше толкование по физике прибора, в SIS не сказано.
- **Нейтральные события (#6/#7).** В SIS слово «neutral» есть только у гистограмм (4.2.1.5), не у счётчиков; строки #6 (детектор E) и #7 (D) — «сработал D/E, молчат F1L, BU, C2H, C2L, CU, F2H». **Стабильный ряд через годы защитить нельзя:** (а) логика #6 изменилась: в 2012 нет `EM`, в 2017 и 2026 есть; скорость 2,83 → 0,82 → 0,54 /с; (б) логика #7 та же, но антисовпадательный канал F1L в 2012 был `F1L-x1`, в 2026 `F1L-x8` с другим порогом (DAC 106 → 101); скорость 4,28 → 2,26 → 1,13 /с при скорости BU 7,85 → 9,37 → 7,01 /с (отношение уходит в 4 раза). Конфигурация (EVIL-таблица) в RDR идентификатором не передана. При QC бит 2 (DAN) счёт нейтральных неверен.
- **Малая доза без QC.** В SIS указаний нет. Эмпирически: наблюдение 13 сола 10 (`QC=00000000`, доза 0,22 мкГр/ч при ≈ 9) имеет скорость BU 0,03 /с при норме ≈ 8, т. е. скорость BU — независимый признак «прибор почти не считал» (корреляция с дозой 0,89). В солах 1649, 1650 и 4843 все наблюдения с аномально низкой скоростью имели QC≠0.
- **Покрытие дозы.** Доза — одно число на наблюдение в мкГр/ч, без маркеров пропуска; учёт мёртвого времени в SIS не описан `[не проверено]`. Наблюдение 960–961 с (живое время 909–930 с), старт каждые ≈ 17 мин: сутки покрыты ≈ на 94 % (1649: 89 дозовых наблюдений, Σ 82 589 с за 26 ч интервала файла); в сол 10 — раз в час (26×960 с ≈ 27 %). Показатель покрытия нужен. SIS упоминает «dose weighted equivalent (DWE)», но в файлах его нет (4 файла).

### Вопрос 3. Колонка и среднесуточная скорость
- «COUNTER_L2 №4» — строка блока `[COUNTER_L2: NN]` с `entry` = 4, вторая колонка `count` (целое, события за наблюдение). Формат одинаков в 2012, 2017, 2026: 10 строк (0–9) в раннем, 13 строк (0–10, 12, 14) в новых; **искать по номеру `entry` и проверять логику `BU`**, а не по позиции. Живое время детектора B — `[COUNTER_L1]`, строка `"BU-x8"`, колонка `duration` (960 с в 2012; 909–930 в 2017; 930 в 2026) и `alive %`; `OBS_DURATION` (961) в раннем формате нет.
- Маркеры `-1`/`-2` в `count`/`duration` строки BU и в `OBS_DURATION` ни разу не встретились; по SIS `-1` — канал не активен, `-2` — данных нет: такие наблюдения пропускать.
- Среднесуточная скорость (Σ count / Σ `duration` BU-x8, только QC=0), три файла: сол 10 — 7,85 /с; 1649 — 9,44 /с (84 наблюдения); 4843 — 7,05 /с (86). Деление на `OBS_DURATION` даёт на 5–6 % меньше (8,94 и 6,82): считать по живому времени (счёт идёт, пока прибор «жив»). Среднее скоростей по наблюдениям совпадает с взвешенным до 0,1 % при QC=0. Без фильтра QC скорость занижена на 0,6–0,8 % (1649: 9,37 против 9,44; 4843: 7,01 против 7,05).

### Рекомендации для спецификации
1. **Сол** = `START_SOL` файла; файлы одного сола — дубли: для сола с несколькими файлами брать один (с максимальным `CREATION_TIME`, т. е. последний по имени), остальные не качать. Для проверки на дубль в остальных солах: `HEAD` (Content-Length; поддержка сервером `[не проверено]`): равный размер — дубль; иначе качать и дедуплицировать по ключу `(START_SOL, START_OBS_UTC, тип EHP/ESD)`, при конфликте значений — приоритет у последнего `CREATION_TIME` и запись в журнал. Совпадение часов в файлах соседних солов дублем не считать.
2. **Скорость счёта** (events/s): `Σ count(entry 4) / Σ duration(BU-x8)` по дозовым наблюдениям с `QC = 0` и без выброса «скорость BU наблюдения < 0,5 × медиана дня». Подпись: «сырая скорость счёта детектора B, событий в секунду живого времени». Проверки: `entry` 4 присутствует и логика `BU`, иначе наблюдение пропускается; `-1`/`-2` пропускаются; `count` ≠ `read` — предупреждение.
3. **Доза за сутки**: среднее, взвешенное по длительности (Σ доза·длительность / Σ длительность), по тем же наблюдениям; длительность — `OBS_DURATION`, при отсутствии — `duration` BU-x8; в ответ — `coverage` = Σ длительностей / 88 775 с и число отброшенных наблюдений. Биты QC: бит 0 — исключать; биты 2 (DAN) и 3 (Solar Event) — для дозы не исключать (реальные данные; Solar Event полезно показать признаком), для нейтральных — исключать; QC разбирать и в кавычках, и без (ранний формат).
4. **Нейтральные события не публиковать** как ряд (логика №6 менялась, пороги №7 менялись, SIS молчит, при DAN искажены). Если владелец настоит: только №7 (детектор D) с пометкой «не сравнимо между периодами».
5. **Загрузчик**: сверка md5 с `CHECKSUMS.TXT`, повтор файла целиком при обрыве (1 из 5 запросов), таймаут ≥ 120 с на файл, потоковый разбор (файлы 12–72 МБ).
6. **Фикстуры для `qa-engineer`** дополнительно: два файла сола 1649 с разной шапкой и одинаковым телом (шапки B3/B4 + 2 наблюдения) и наблюдение со `START_OBS_MARS` и скачком UTC.

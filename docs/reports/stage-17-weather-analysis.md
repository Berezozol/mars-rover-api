## 2. MEDA

### Какие продукты дают суточные значения
| Величина | Продукт | Колонки | Единицы |
|---|---|---|---|
| Воздух | `calibrated_env` `CAL_ATS` | `ATS_LOCAL_TEMP1..5` | К |
| Ветер | `calibrated_env` `CAL_WS` (идентичен по солам `derived_env/WS`) | `BOOM{1,2}_HORIZONTAL_WIND_SPEED` (м/с), `BOOM{1,2}_WIND_DIRECTION` (°), `BOOM{1,2}_ALG_STATE_STABLE`, `ROVER_STILL`; вертикальная скорость и все неопределённости **пусты** | м/с, ° |

- **Время**: `SCLK` (с), `LMST` (`00136M00:00:00.471`), `LTST`. Сол = первые 5 цифр `LMST`; строк с чужим солом в `CAL_ATS` нет (0 на 1754 солах).
- **Частота `CAL_ATS`**: 2 Гц (шаг 0,5 с) на ≈ 120 из первых 182 солов и редко позже, остальные 1 Гц; 31–125 тыс. строк на сол. Съёмка сеансами: покрытие сутки по 10-минутным корзинам (148 в соле): медиана 0,59, ≥ 0,9 — 73 сола, < 0,1 — 11 солов (1, 2, 9, 10, 14, 165, 416, 1224, 1226, 1230, 1279). Все 24 часа LMST задеты в 1465 солах, ≥ 18 часов — в 1599, ≥ 12 — в 1695.
- **Пропуски и флаги**: `CAL_ATS` — без `999999999` и пустых полей, **флагов нет**; `PS`, `RHS` — `999999999`/пусто (`PS` сол 10 целиком нет); `CAL_WS` — пусто, когда боом не отдал значение; флаги стабильности бума и `ROVER_STILL` (в 90–100% строк = 1).
- **Температура воздуха — какой датчик.** Метка: `TEMP1/2/3` — на мачте RSM (50°, 155°, 290°), `TEMP4/5` — на переднем борту ровера (RFB, левый/правый). Высот в метке нет [не проверено]. Относительно медианы T1–T3 (сутки, 1754 сола): T1 среднее +0,3 К, T2 +1,2 К, T3 +1,4 К; **T4 +5,5 К (макс. +19 К у 95-го перцентиля), T5 +3,9 К (+17 К)**: борт греется от ровера и Солнца. Даже у T2/T3 дневной максимум выше медианы в среднем на 0,8/2,9 К. Вывод: **«воздух» = медиана `T1,T2,T3` в каждой строке** (устойчива к солнечному нагреву одного датчика); T4/T5 не использовать.
- **Что показывает ветер:** только солы 36–313 (263 сола с данными; 313 последний с непустой скоростью, `CAL_WS` файлы до 315). **Ни `CAL_WS`, ни `DER_WS` не продолжаются дальше 315 сола**: ветра MEDA после этого в PDS нет. Скорость: среднее по солу 1,2–5,1 м/с (медиана 3,0), 99-й перцентиль внутри сола 4–25 м/с, **но дневной максимум до 52 м/с** (129 из 263 солов > 25 м/с) — это выбросы датчика, физических порывов на Марсе столько не бывает. Направление: длина среднего вектора R медиана 0,21 (направление в течение сола очень изменчиво), «круговое среднее» малоинформативно; сектор-мода (16 румбов) устойчивее. Конвенция направления в метке MEDA не описана [не проверено] (у REMS описана: «откуда дует», по часовой от севера).

### Алгоритм суточной свёртки MEDA (предлагаемый)
Поток, по строке:
1. Сол файла = сол из имени; строки с другим первым полем `LMST` отбросить. Если несколько версий `P0V` — брать старшую, версию сохранить (`source_version`).
2. `hour = floor(LMST_секунд / 3600)` (0–23), `bin10 = floor(сек / 600)`.
3. Температура: `T = median(T1,T2,T3)`, если все три в 100–400 К, иначе строка пропускается.
4. Давление: `PRESSURE` не пусто, не `999999999`, 100–2000 Па. Влажность: 0–100 %.
5. Ветер: по бумам с `ALG_STATE_STABLE = 1` и значениями скорости/направления; `speed = среднее валидных бумов`; `ROVER_STILL` не фильтровать (в 99% солов ≥ 90% строк = 1), но писать долю.
6. Накопители: min, max, сумма, n, сумма и n по часам, набор корзин bin10, набор часов; для ветра — векторная сумма (sin, cos) и гистограмма 16 секторов (по 22,5°, центр на север); перцентиль 99 скорости (по отсортированному списку суточных значений ≤ 125 тыс.).
7. Итог за сол: `min`, `max` (сырые экстремумы; у температуры и давления физичны), **`mean` = среднее по почасовым средним** (а не по строкам — иначе сеансовая съёмка искажает: разница со «строчным» средним у температуры в среднем 1,25 К, до 11,5 К; у давления в среднем 0,5 Па, до 8,7 Па), `coverage = |bin10| / 148`, `hours_covered = |часы|`.
8. Ветер: `wind_mean` (почасовое среднее), **`wind_gust = p99` вместо max** (max брать нельзя: выбросы до 52 м/с), `wind_dir_mode` (румб с наибольшим числом точек), `wind_dir_R` (устойчивость).

**Неполные солы:** хранить всегда с `coverage` и `hours_covered`. `mean` публиковать только при `hours_covered ≥ 18` (1599 из 1754 солов, 91%), иначе `null`; `min/max` публиковать, но при `coverage < 0.3` пометить «неполный сол» (min/max — по наблюдавшемуся окну, настоящий минимум ночи мог не попасть в окно). Пример предела: сол 1230 — покрытие 0,054, влажность среднее 47,6% (только ночь): без порога выводит в заблуждение.
Влажность: суточное среднее имеет смысл только при `hours_covered ≥ 18`; в абсолютных единицах (VMR) — отдельно [не рекомендую в API]. Сол 1852–1853: у 977–1601 строк влажности > 100 % (фильтр отбросил).

## 3. REMS (`RMD`, солы 1–71 из ≈ 4703 файлов)

### Колонки (порядок по метке `.xml`, `.TAB` — CSV-подобный: запятые, строки в кавычках, фиксированная ширина 372 Б)
`TIMESTAMP, LMST, LTST, HORIZONTAL_WIND_SPEED, VERTICAL_WIND_SPEED, WIND_DIRECTION, WS_CONFIDENCE_LEVEL, BRIGHTNESS_TEMP(+2 неопр.), GTS_CONFIDENCE_LEVEL, BOOM1_LOCAL_AIR_TEMP, ATS_BOOM1_CONFIDENCE_LEVEL, BOOM2_LOCAL_AIR_TEMP, ATS_BOOM2_CONFIDENCE_LEVEL, AMBIENT_TEMP, AMBIENT_TEMP_CONFIDENCE_LEVEL, UV_A/B/C/ABC/D/E (+6 неопр.), UVS_CONFIDENCE_LEVEL, LOCAL_RELATIVE_HUMIDITY, HS_TEMP, …_UNCERTAINTY, VOLUME_MIXING_RATIO(+неопр.), HS_CONFIDENCE_LEVEL, PS_CONFIGURATION, PRESSURE, PRESSURE_UNCERTAINTY, PS_CONFIDENCE_LEVEL` — **ровно 40 колонок, порядок подтверждён метками сол 70 и 71 и данными** (файл `MODRDR6.FMT` не нужен). Единицы: К, Па, м/с, Вт/м², %; пропуск `-999.00` (числа) и `XXXX…` (маски).

### Частота, пропуски, флаги
- Шаг 1 с, сеансами (16–38 тыс. строк на сол, `cov` по 10-минутным корзинам 0,02–0,5, медиана 0,33). Все 24 часа LMST задеты не везде (по `amb_good_hours`: медиана 24, есть солы с 1–19).
- `AMBIENT_TEMP` заполнен во всех строках (оценка воздуха, не измерение, но «лучшая оценка»); `BOOM1/2_LOCAL_AIR_TEMP` содержат глитчи (мин. 92 К на `BOOM2`).
- Маска `AMBIENT_TEMP_CONFIDENCE_LEVEL` (9 символов): byte 0 «ASIC > −50 °C» (ночью = 0 — **не использовать как фильтр**: выбрасывает ночь), byte 7 «ошибка < 5 К», **byte 8 «наблюдение надёжно»** (всегда 1 на проверенных солах). Рабочий фильтр: `byte7 = 1 и byte8 = 1`. Влияние: среднее по `all` выше `good` на 1,0 К в среднем (до 3,6 К), min `good` на 0,1–0,9 К ниже, max на 0,4 К в среднем (до 10,4 К — нагрев).
- Давление: `PRESSURE`, неопр. 2,7 Па; маска `PS_CONFIDENCE_LEVEL` из двух символов (генератор, «тень»). Заполнен во всех строках; в `good` (byte1 = 1) ≥ 98%.
- Грунт: `BRIGHTNESS_TEMP` — есть фильтр: `GTS_CONFIDENCE_LEVEL` byte 0–1 = 1; без него min 92,6 К (глитч), с ним 134–153 К (сол 36 134 К — всё ещё мало, но возможно холодная ночь).
- Влажность: `HS_CONFIDENCE_LEVEL` на этих солах `0X0`/`0X1` — «предварительная» (byte 0 = 0), значения 0–33%, медиана среднесуточных 3,8% — **ненадёжна, как и у MEDA, для API лучше пометить `preliminary`**.
- УФ: `UV_ABC` 0–21 Вт/м², маска UV 5 символов; суточный max 1,8–21,1 Вт/м² (медиана 19,2), среднее 0,08–8,9.
- **Ветер REMS**: на солах 1–71 `HORIZONTAL_WIND_SPEED` валиден только в 7–60 строках за сол (медиана 25–30), `WS_CONFIDENCE_LEVEL` в остальных `XXXXXX`; скорость 5–20 м/с (завышено — вероятно, только порывы); направление в метке: «откуда дует, по часовой от севера». Суточное среднее ветра REMS ненадёжно, **не включать**. Повреждение ветрового датчика (≈ сол 1500 и далее) проверить нельзя до загрузки.

### Алгоритм REMS (предлагаемый)
Как для MEDA (шаги 1–2, 6–7), с отличиями: воздух — `AMBIENT_TEMP` при `byte7 = byte8 = 1` (если `byte8 = X`, строку отбросить), давление — `PRESSURE` (!= −999 и `byte1 = 1`), грунт — `BRIGHTNESS_TEMP` при `GTS byte0 = byte1 = 1`, влажность — как есть + `preliminary`, УФ — `UV_ABC` (≥ 0), ветер — не публиковать. Те же `coverage` и порог `hours_covered ≥ 18` для среднего.

## Открытые вопросы владельцу (с рекомендацией)
1. Публиковать ли `mean` у неполных солов: рекомендую `null` при `hours_covered < 18` (9% солов), `min/max` отдавать с `partial: true`.
2. Ветер: у Perseverance только солы 36–313 (≈ 15%), у Curiosity (ранние солы) непригоден; рекомендую выдавать ветер только у Perseverance, у остальных `null` и пометить в документации.
3. Грунт Perseverance: готового значения нет (TIRS даёт потоки); рекомендую не показывать.
4. Влажность: «предварительная» у обоих; рекомендую включить с пометкой `preliminary`.
5. Объём: есть ли смысл в часовых данных (15–20 МБ)? Рекомендую пока нет.
6. Сырые файлы (~70 ГБ после REMS) после свёртки удалять только после сверки; источник перевыпускает продукты, писать `source_version`.

# Доработка: цена процессора больших ответов v1 (MEDIUM-2)

Редакция 1 (2026-11-22, HEAD `a9023e3`, миграции до `0015`). Основа: находка MEDIUM-2 ревью безопасности коммита `a9023e3`; `docs/proposals/legacy-response-size.md` (разделы 3 и 5); `docs/API.md`, «Ограничение частоты (v1 и v2)», пункт «Размер ответов v1»; `docs/LEGACY-API.md`, таблица расхождений; код `app/api/ratelimit.py` (`ResponseSizeMiddleware`, `extra_hits`), `app/api/caching.py` (`_CachedResponse._flush`), `app/main.py`; замер в процессе на dev-базе `mars` (скрипт в scratchpad, только чтение).

## 0. Цель, границы, критерий

**Входит:**
- цена ответа v1 в лимите частоты — большее из двух: начатые 256 КиБ тела на проводе (как сейчас) и начатые `RATE_LIMIT_V1_RAW_BYTES_PER_REQUEST` (1 МиБ) несжатого тела, которое сервер построил; так gzip, `HEAD` и `304` перестают делать весь сол дешёвым;
- несжатый размер сообщает прослойка кэширования (она и так держит тело целиком), без второго прохода по телу.

**Не входит:** кэш готовых ответов v1 по солам (вариант «в» ADR); серверный шлюз больших ответов (вариант «б»); v2 (страницы до 100 снимков); защита от распределённой атаки со многих адресов.

**Готово, когда:** с одного IP запросы `GET /api/v1/rovers/curiosity/photos?sol=0` с gzip (и `HEAD`, и `304`) стоят по 8 запросов, то есть не больше ~8 в минуту, а обычные солы с gzip по-прежнему стоят один запрос (AC-1…AC-9 зелёные, полный прогон зелёный).

## 1. Факты

1. Замер (dev-база, приложение в процессе, медиана из 5, с gzip): curiosity sol 0 — 4370 снимков, 8 008 724 байта несжатого JSON, 137 844 байта gzip, **~250 мс** на запрос; `HEAD` — те же ~220 мс и 0 байт тела; sol 1000 — 23 КБ, 10 мс; страница `page=1` (25 снимков) — 16 мс. Из 250 мс: sha256 тела — ~4 мс, gzip — ~60 мс (уровень 9 вне сервера; у Starlette свой уровень), остальное — выборка, построение словарей и `to_json` `[разделение по частям не проверено]`.
2. Сейчас (`a9023e3`) цена — только по байтам на проводе: sol 0 с gzip стоит 1 запрос, `HEAD` и `304` — 1. 60 таких запросов в минуту с одного IP — ~15 с работы из каждых 60, около четверти цикла событий.
3. `_CachedResponse._flush` (`app/api/caching.py`) собирает тело 200-ответа целиком (`body = b"".join(...)`) до хэша и до замены на `304`/пустое тело `HEAD` — здесь известен несжатый размер. Для `HEAD` `scope` копируется (`_as_get`: `{**scope, ...}`), значения-словари в нём общие.
4. `ResponseSizeMiddleware` стоит снаружи `GZip` и считает байты на проводе; `_CachedResponse` — внутри всех (`app/main.py`). Порядок: `VaryAcceptEncoding` → `ResponseSize` → `GZip` → `CORS` → `RateLimit` → `Caching` → приложение.
5. Распределение (dev-база, редакция 1 `legacy-response-size.md`, п. 1.3): ~1,8 КБ на снимок v1; 1 МиБ несжатого — ~580 снимков; 99-й перцентиль солов Curiosity — 588 снимков, Perseverance — 1239; солов больше 1000 снимков — 3 у Curiosity и 35 у Perseverance.

## 2. Критерии приёмки

Тестовые единицы: `U` = `RATE_LIMIT_V1_BYTES_PER_REQUEST` (например, 1024), `R` = `RATE_LIMIT_V1_RAW_BYTES_PER_REQUEST` (например, 4096); тела — тестовые маршруты v1, как в `tests/api/test_response_size_limit.py`.

| № | Критерий (вход → результат) | Кто проверяет | Слой теста |
|---|---|---|---|
| AC-1 | `response_cost(wire, raw, unit, raw_unit)` → `max(1, ceil(wire/unit), ceil(raw/raw_unit))`; `raw` неизвестен (`None`) → как раньше, только по `wire` | qa-engineer | unit |
| AC-2 | GET v1 c `Accept-Encoding: gzip`, несжатое тело `10 × R`, хорошо сжимаемое → списано 10 запросов (раньше 1) | qa-engineer | api |
| AC-3 | `HEAD` того же ресурса → списано 10 запросов, тело пустое, заголовки как раньше | qa-engineer | api |
| AC-4 | GET с совпавшим `If-None-Match` (`304`) → списано 10 запросов | qa-engineer | api |
| AC-5 | GET без gzip, тело `B` → списано `max(ceil(B/U), ceil(B/R))` (при `R ≥ U` — по-прежнему `ceil(B/U)`, поведение `a9023e3` не меняется) | qa-engineer | api |
| AC-6 | Тело v1 ≤ `R` с gzip → 1 запрос; v2 с любым телом, пути без лимита → 1 запрос (без доплаты), как раньше | qa-engineer | api |
| AC-7 | Ответы не 200 (`4xx`, `503`, `3xx`) → несжатый размер не сообщается, цена только по проводу | qa-engineer | api |
| AC-8 | `RATE_LIMIT_V1_RAW_BYTES_PER_REQUEST` по умолчанию 1 048 576; меньше `RATE_LIMIT_V1_BYTES_PER_REQUEST` или меньше 1024 → ошибка настроек при старте | qa-engineer | unit |
| AC-9 | Существующие тесты `test_response_size*` и лимита → зелёные; ожидания меняются только там, где тело с gzip/`HEAD`/`304` больше `R` | qa-engineer | все |

## 3. Решения

1. **Цена — максимум из двух счётчиков, а не сумма.** Провод защищает канал (решение `a9023e3`), несжатый размер — процессор; максимум не наказывает дважды и сохраняет «обычный сол — один запрос».
2. **Единица несжатого — 1 МиБ (в 4 раза крупнее проводной).** Sol 0 Curiosity (8 МБ) с gzip, `HEAD` или `304` стоит 8 запросов → ≤ 7–8 в минуту с IP → ~2 с работы в минуту (~3% цикла) вместо ~15 с. Солы до ~580 снимков (больше 99% у Curiosity) с gzip по-прежнему стоят 1.
3. **Размер сообщает `_CachedResponse`.** `ResponseSizeMiddleware` кладёт в `scope` изменяемый словарь (`scope["mars.response_size"] = {}`), `_flush` записывает туда `len(body)` до хэша и до обнуления тела; копия `scope` для `HEAD` ссылается на тот же словарь. Тело второй раз не читается.
4. **Только v1** — как и проводная доплата.
5. Контракт меняется (цена в лимите) — текст в разделе 4, нужно «ок» владельца.

## 4. Текст для контрактов (нужно «ок» владельца)

**`docs/API.md`, пункт «Размер ответов v1»** — заменить первое и второе предложения на:

> - **Размер ответов v1.** Ответ на путях v1 (`/api/v1/*`, `/mars-photos/api/v1/*`) стоит в обоих окнах большее из двух чисел, но не меньше одного запроса: сколько начатых `RATE_LIMIT_V1_BYTES_PER_REQUEST` (по умолчанию 262 144 байта, 256 КиБ) в теле в том виде, в каком оно ушло клиенту (после сжатия gzip), и сколько начатых `RATE_LIMIT_V1_RAW_BYTES_PER_REQUEST` (по умолчанию 1 048 576 байт, 1 МиБ) в несжатом теле, которое построил сервер, — в том числе для `HEAD` и `304`, где тело не отправляется. Ответ до 256 КиБ стоит, как и раньше, один запрос; список снимков всего сола Curiosity без `page` (8 МБ) — 31 запрос без сжатия и 8 — со сжатием (`Accept-Encoding: gzip`, ~140 КБ), а также для `HEAD` и `304`.

**`docs/LEGACY-API.md`, строка «большой ответ (весь сол без `page`)»**, третья колонка:

> ответ полный, но в лимите частоты стоит большее из: начатые 256 КиБ тела после сжатия и начатые 1 МиБ несжатого тела (также для `HEAD` и `304`): весь сол Curiosity (8 МБ) — 31 запрос без gzip, 8 — с gzip (`API.md`, «Ограничение частоты»)

## 5. ADR

| Вариант | Плюсы | Минусы |
|---|---|---|
| **(а) цена по несжатому размеру, единица 1 МиБ (рекомендую)** | ограничивает работу сервера с одного IP при любом `Accept-Encoding`, `HEAD`, `304`; дополняет уже выложенный механизм (одна функция и один словарь в `scope`); честные клиенты с обычными солами не замечают | клиент с gzip, который скачивает самые большие солы целиком, упрётся в лимит раньше (~8 таких в минуту) |
| (б) серверный шлюз больших ответов v1 | ограничивает одновременную работу со многих IP | не ограничивает суммарную работу (места занимаются подряд); честный клиент получает `503` из-за чужих запросов |
| (в) кэш готовых тел v1 по солам | честные повторные запросы почти бесплатны, ETag без пересчёта | память (до 8 МБ на сол, тысячи солов — атакующий перебирает солы и вытесняет кэш), сброс при синхронизации; от перебора солов не защищает |

Остаточный риск: распределённая атака со многих IP — общий для всех лимитов по IP; (б) и (в) можно добавить позже поверх (а).

## 6. Модель данных, миграция, поток

Миграций нет. Поток: `ResponseSizeMiddleware` (v1, лимитер есть) → `scope["mars.response_size"] = {}` → … → `_CachedResponse._flush`: если ключ в `scope`, записать `raw` = `len(body)` до 304/HEAD → ответ уходит → `finally`: `charge(key, response_cost(sent, info.get("raw"), U, R) − 1)`.

## 7. Задания ролям и общие имена

**Общие имена:**
- `Settings.rate_limit_v1_raw_bytes_per_request: int = 1_048_576` (env `RATE_LIMIT_V1_RAW_BYTES_PER_REQUEST`, ≥ 1024 и ≥ `rate_limit_v1_bytes_per_request`);

- `backend-dev`: настройка и `.env.example`; `response_cost`; словарь в `scope` и запись `raw` в `_flush`; подключение в `ResponseSizeMiddleware`; `README.md` и `/llms.txt` — одна правка фразы о цене (README через `tech-writer`).

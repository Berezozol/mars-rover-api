# Миниатюры Curiosity из фида JPL в `images.small`

Редакция 1 (2026-11-24, HEAD `e442c83`, миграции до `0019`). Основа: `docs/reports/msl-thumbnails.md` (сопоставление миниатюра → кадр, 28 запросов), `docs/DATA-SOURCES.md` (раздел «Миниатюры → кадры»), ADR-4А в `docs/proposals/api-v2-ui-improvements.md`, решение владельца 2026-11-24.

## 0. Цель, границы, критерий

**Входит:**
- у снимков Curiosity камер Mastcam (`MAST_LEFT`, `MAST_RIGHT`), MAHLI и MARDI в `img_small` пишется URL миниатюры JPL (до 192×144, по форме кадра) из фида;
- шаг «миниатюры сола» в синхронизации MSL и разовый добор истории отдельной командой;
- карточка снимка Curiosity по-прежнему открывается полным кадром, миниатюра — только для сеток и превью.

**Не входит:** миниатюры Navcam, Hazcam, ChemCam RMI (64×64 или отсутствуют — решение владельца 2026-11-24); свой ресайз; изменения v1 (`img_src` остаётся полным кадром); миниатюры Perseverance (уже есть свои размеры).
**Готово, когда:** на проде `GET /api/v2/rovers/curiosity/photos?sol=5073&camera=MAST_LEFT` отдаёт у снимков `images.small` с миниатюрой, сетка Sol Index грузит миниатюры, карточка — полный кадр.

## 1. Факты

- Ключ сопоставления для MSSS (Mastcam, MAHLI, MARDI): первые 22 символа `imageid`; URL миниатюры совпал с URL, полученным заменой буквы продукта (и версии на `01`) в URL кадра, в 3 012 из 3 012 пар (`docs/reports/msl-thumbnails.md`, раздел 1).
- Буквы: кадр `C00`, `D01–D03`, `E01–E0C` → миниатюра `I01`; MAHLI `R00` → `T01`, `S00` → `U01` (там же).
- У кадра не бывает двух миниатюр; одна миниатюра может относиться к 2–3 кадрам одного снимка (`C00` + `E0x`) — общая миниатюра для них корректна.
- Миниатюры из фида: `extended=thumbnail::sample_type::eq`, `per_page=1000`, пачки солов `a,b,…:sol:in` — проверено; всего ~730 тыс. миниатюр MSL (все камеры).
- Миниатюры приходят в фид раньше кадров (солы 5077, 5083).
- Миниатюра субкадра показывает сам субкадр и повторяет его форму (AC-9 пройден): размер до 192×144, бывает 160×144, 144×144, 80×112 — плитка сетки вписывает картинку (`object-fit`), не растягивает.
- Сейчас у Curiosity `images.small` — `null` (`docs/API.md`, «Объекты»); карточка (`frontend/src/pages/Photo.tsx:317`) выбирает по умолчанию `medium`, затем `small`, затем `full` — с миниатюрой карточка открылась бы на 192×144.

## 3. Решения

1. Только MSSS-камеры: Mastcam (`MAST_LEFT`, `MAST_RIGHT`), MAHLI, MARDI — решение владельца 2026-11-24 (Navcam и Hazcam 64×64, в плитке мыло).
2. Миниатюры берём из фида (способ Б отчёта), а не по правилу имени: правило без запроса даёт битые ссылки там, где миниатюры нет.
3. Пишем только при найденной паре; миниатюра без кадра не хранится (снимков без кадра у нас нет).
4. Отдельная таблица не нужна: `photos.img_small` уже есть; миграции нет.
5. Карточка Curiosity открывается полным кадром — миниатюра не годится как основной вид.
6. MARDI: кадры видео `M0x` сопоставляются с миниатюрой `Q01` (192×144) — решение владельца 2026-11-24 после добора (MARDI было 27,5%). Только для MARDI (`…MD…`): у Mastcam `Q01` — 16×16 и 64×64, не берём (`docs/reports/msl-thumbnails.md`, «Буква `Q01`»). AC-11 ниже.

**AC-11.** MARDI: кадр `…MD…M01_DXXX` и миниатюра `…MD…Q01_DXXX` с тем же ключом → `img_small` записан; Mastcam `…ML…M0x`/`K01` и миниатюра `…ML…Q01` → ключ `None`, `img_small` не пишется; миниатюра `I01` у кадра MARDI по-прежнему работает. Проверяют: qa-engineer (unit + integration); data-engineer — доля MARDI после повторного добора.

## 5. ADR

- **Источник миниатюр.** А — перезагрузка истории без фильтра (≥ 7,6 тыс. страниц, перезапись кадров); Б — только миниатюры фильтром (~1 тыс. запросов); В — правило имени без запросов (~8% битых). Выбрано Б.
- **Где искать пару.** По ключу в памяти пачки солов: миниатюры пачки → словарь ключ → URL → обновление `photos` этих солов одним `UPDATE … FROM (VALUES …)`.

## 6. Модель данных, миграция, поток

- Миграции нет; `photos.img_small` — существующий столбец.
- Поток: фид (`thumbnail::sample_type::eq`, пачка солов) → адаптер MSL (`fetch_thumbnails(sols)`, `thumbnail_key(imageid)`) → сервис (сопоставление с кадрами сола по ключу, только камеры из `MSL_THUMBNAIL_CAMERAS`) → `UPDATE photos SET img_small` там, где значение другое.
- В `sync` — шаг после кадров сола; в разовой команде — пачки по 20 солов (≤ 1000 записей на страницу, при большем `total` — страницы), пауза между запросами как у синхронизации.
- Идемпотентно: повторный проход не меняет строки с тем же URL.
- Повторная синхронизация кадров не стирает `img_small`: upsert `photos` не затирает его `NULL` от источника (решение после ревью, все марсоходы; `docs/ARCHITECTURE.md`, «Идемпотентность»).
- Запрос миниатюр в синхронизации уходит только для сола, где есть кадры `MSL_THUMBNAIL_CAMERAS` (после ревью — без лишних запросов на пустые солы и солы только с Navcam).

## 7. Задания ролям и общие имена

**Общие имена:** `app/sources/msl.py` — `thumbnail_key(imageid: str) -> str | None`, `fetch_thumbnails(client, sols) -> list[Thumbnail]`; `app/services/thumbnails.py` — `apply_thumbnails(session, rover, sols) -> ThumbnailResult(matched, updated, skipped)`; константа `MSL_THUMBNAIL_CAMERAS = {"MAST_LEFT", "MAST_RIGHT", "MAHLI", "MARDI"}`; CLI `python -m app.cli thumbnails --rover curiosity --from-sol --to-sol`; фикстуры `tests/fixtures/upstream/msl/thumbnails_sol_<N>.json`.

- `backend-dev`: адаптер, сервис, шаг в синхронизации, CLI; `docs/openapi.json` не меняется.
- `qa-engineer`: AC-1…AC-7; фикстуры миниатюр — через `/record-fixtures` (тимлид, запросы к фиду).
- `frontend-dev`: `Photo.tsx` — для Curiosity по умолчанию `full` (AC-8); сетки уже берут `small`.
- `frontend-qa`: AC-8.
- `data-engineer`: AC-9 до добора, затем добор на базе разработки и AC-10.
- `tech-writer`: строка про миниатюры Curiosity в README/`/developers`, если там описаны размеры.
- `devops`: добор истории на VPS после выкладки (`thumbnails --from-sol 0 --to-sol` = последний сол Curiosity в базе).

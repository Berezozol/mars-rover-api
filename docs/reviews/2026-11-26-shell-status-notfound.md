## Насколько дизайн «свой»

- **Layout:** честно стандартная для Operate оболочка; своё — знак «планета с горизонтом» в ржавом акценте, тихая пометка `unofficial`, меню «Data» с подписанным марсоходом («Radiation — Curiosity»). Слабое место — информационная архитектура: глобальные пункты и пункты марсохода стоят в одном ряду.
- **Status:** шаблон статус-страницы; продукт думает в солах, а свежесть показана только земными датами.
- **NotFound:** типовой пустой экран, не использует ни язык продукта, ни сам адрес.

## Что работает (проверено)

- Skip link: первый Tab, Enter → фокус в `<main>`. `aria-current` верен на всех маршрутах. При переходе — `scrollY 0`, фокус в `main`, `document.title` обновляется.
- Меню «Data» — disclosure: `aria-expanded`, `aria-controls`, Esc с возвратом фокуса, закрытие кликом вне и уходом фокуса; на 375 раскрывается на всю ширину.
- Тема: следует системе, выбор переживает переходы и перезагрузку, скрипт в `<head>` (`index.html:28-34`) ставит тему до отрисовки — вспышки нет; `meta color-scheme`. Контраст всех токенов ≥ AA в обеих темах.
- Внешних хостов нет; ассеты `immutable` на год, HTML `no-cache` + ETag; `prefers-reduced-motion` гасит shimmer.
- Подвал: «independent, unofficial… not affiliated with or endorsed by NASA or JPL. Image credit is shown next to every photo» — точно по правилам проекта.
- Status устойчив: при ошибке прошлые данные остаются, обновление раз в 60 с только на видимой вкладке, `<time datetime>`, статус всегда текстом, не только цветом.

## Находки

### Layout

**P1**

1. **Глобальная и марсоходная навигация смешаны, контекст марсохода теряется.** На Curiosity пункты Photos/Timeline/Route map ведут на Curiosity, после Search/Stats/Data — молча на Perseverance (`Layout.tsx:135-144`, `own ?? list[0]`; проверено: после `/data/weather` «Photos» → `/rovers/perseverance`). На карте, Samples и Flights — ещё ряд `view-tabs` с теми же словами (`RouteMap.tsx:131`, `Samples.tsx:113`, `Flights.tsx:122`), на Photos и Timeline его нет; «Flights» в «Views of Perseverance» уводит на Ingenuity. До контента на карте — 4 слоя навигации.
   - AC: «в шапке только глобальные пункты (Rovers, Search, Data, Stats, API docs); на всех страницах марсохода — один ряд вкладок вида под переключателем марсохода; переход из `/data/weather` в раздел марсохода ведёт на последний открытый марсоход или явно его называет».
2. **Мобильная навигация прячет больше половины пунктов.** На 375 `.nav` прокручивается вбок (`scrollWidth 675` / `clientWidth 343`), полосы прокрутки нет (`scrollbarThickness 0`), маски нет; активный пункт не доскролливается (на `/data/weather` кнопка «Data» на x 478–550 — целиком за экраном); `overflow-y:hidden` при высоте 37 px режет контур фокуса 3 px + offset 2 px (по расчёту, глазами не подтверждено). `styles-base.css:669-684`, `Layout.tsx:181-211`. WCAG 2.4.7.
   - AC: «375 → активный пункт навигации виден без прокрутки; у края полосы видимый признак продолжения (или меню “More”); контур фокуса пункта не обрезан».

**P2**

3. **Подвал:** ссылки 21 px высотой в двух рядах без подписей групп, «Delete my data» вплотную к «My keys», Status только здесь и без `aria-current` на `/status` (`Layout.tsx:225-241`, `app.css:29-34`).
   - AC: «375 → ссылки подвала ≥ 44 px по высоте, группы подписаны; на `/status` ссылка Status с `aria-current`».
4. **Кнопка темы:** подпись называет целевое состояние («Dark» в светлой теме) и читается как текущее; в «как в системе» вернуться нельзя (`lib/theme.ts:18-27`); нет слушателя `matchMedia change` — после смены системной темы подпись и `aria-label` врут (воспроизведено), нет синхронизации вкладок (`storage`). WCAG 4.1.2.
   - AC: «переключатель Light / Dark / Auto (Auto удаляет ключ); смена системной темы обновляет подпись».
5. **Границы полей и кнопок 2.4:1** — `--border-strong #a99f93` (`styles-base.css:13`) на `input`, `select`, `.btn`, `.segmented`, `.chip`: светлая 2.37:1, тёмная 2.55:1. WCAG 1.4.11.
   - AC: «граница интерактивных элементов ≥ 3:1 к фону в обеих темах».
6. **Фокус после перехода — на весь `<main>`, а не на h1** (`Layout.tsx:115-122`) — скринридер читает весь контейнер.
7. **Дрейф шкалы кегля:** токены 12/14/16/20/26/34 (`styles-base.css:67-72`), а в DOM 10 px (единицы), 11 px, 11.67 px (UA-размер `<small>`, ~100 узлов), 14.72, 17.6 (`stage19.css:627`).
   - AC: «в DOM нет текста мельче `--fs-xs` (12 px); `small` наследует шкалу».
8. **Тёмные токены записаны дважды** — `styles-base.css:91-135` и `138-181` совпадают построчно; хардкод теней и запасных цветов в `app.css` (`:1362`, 3 × `var(--surface-2, #ddd)`) и `data.css:557`, `700`.

**P3**

- `scroll-padding-top: 72px` (`app.css:3-5`) при шапке 81 px на 375 — якоря уходят под шапку.
- Skip link дописывает `#main` в адрес.
- `index.html`: статичный `<title>` до JS, нет `<noscript>`, `theme-color`; в `document.title` id марсохода строчными («Photos — curiosity»).
- `ErrorBoundary` (`App.tsx:27-60`) оборачивает только страницу — ошибка в Layout даёт пустое приложение; нет «Try again».
- Подвал не прижат к низу на коротких страницах; нет `@media (forced-colors)` и print; значки ✓ ! ✕ — текстовые глифы.
- Пункт «Flights» в шапке появляется по данным — шапка «прыгает» при загрузке.
- Живой логотип и `design/mockups/index.html` различаются — `design/NOTES.md` стоит обновить (расхождение документа и кода, сообщаю).

### Status

**P1**

9. **Заголовок не отвечает на вопрос «свежие ли данные?» и не успокаивает.** У обоих марсоходов синхронизации нет 8 дней, а баннер говорит «Data may be behind»; нет фразы «API работает и отдаёт уже загруженное», наборы Data (погода, радиация, образцы) не покрыты. `Status.tsx:27-31`, `189-195`.
   - AC: «`/status` при `stale` → предложение-факт “Photo sync hasn't run for N days. The API is up and serves photos up to Curiosity sol X / Perseverance sol Y”; раздел Datasets с `updated_at` погоды, радиации, образцов».

**P2**

10. **Свежесть в земных датах, без солов; время смешано** — «Newest photo 2026-11-17» без сола и ссылки; «Last checked 6:40:33 PM» в локальной зоне без указания рядом с UTC (`Status.tsx:51-57`, `157`, `175`).
    - AC: «карточка марсохода → “Newest photo: sol N (дата)” со ссылкой на этот сол; у локального времени указана зона».
11. **Одно предупреждение трижды** — баннер и плашка «! Sync is late…» мелким (12 px) янтарным текстом в каждой карточке (`Status.tsx:60-64`, `stage19.css:642`).
12. **После сбоя обновления остаётся старый «зелёный» вердикт** — добавляется только мелкая серая строка без `role` (`Status.tsx:99-108`, `135`, `173-177`). WCAG 4.1.3.
    - AC: «ошибка обновления → баннер помечен “Last known:”, строка об ошибке объявляется `role=status`».
13. **Страницу трудно найти** — только в подвале (см. №3); `aria-current` нет.

**P3**

- `GET /health/sync` отвечает 503 при `stale` (так задумано контрактом для мониторинга) — каждое обновление пишет ошибку в консоль. Вопрос владельцу, не фронтенду.
- Refresh 73×32 px без видимого индикатора загрузки; живой регион может повторять тот же текст раз в минуту.
- Curiosity первой, хотя везде на сайте первая Perseverance.

### NotFound

**P2**

14. **Нет `h1`** — единственный заголовок `h3` из `EmptyState` (`States.tsx:95`, `NotFound.tsx:8-17`). Общий дефект: тот же `EmptyState` даёт h3 без h1 на «Rover not found» (Photos, Samples, Flights, Timeline, карта) и на 404 отчёта по солу. WCAG 1.3.1, 2.4.6.
    - AC: «`/no-such-page` и `/rovers/nosuch` → ровно один h1 (“Page not found” / “Rover not found”)».
15. **`/photos/abc` даёт технический экран 422** («Please fix the following: id: must be an integer · validation_error (HTTP 422)»), а `/photos/abc/extra` — дружелюбный 404: роутер не проверяет id (`router.tsx:145`), хотя сол проверяет (`:138-143`).
    - AC: «`/photos/abc` → тот же NotFound, что и для неизвестного адреса».
16. **Нет восстановления по контексту** — неверный адрес не показан, одна общая кнопка «Go to the rovers» (32 px), для `/rovers/curiosity/sols/abc/conditions` не предложены страницы Curiosity, нет Search/Status/API docs.
    - AC: «`/rovers/curiosity/…` (неизвестный путь) → показан путь и ссылки “Curiosity photos”, “Curiosity timeline”, “Search”».
17. **Soft 404: сервер отдаёт HTTP 200 на любой неизвестный адрес** (проверено на `/no-such-page`, `/rovers/curiosity/sols/abc/conditions`, `/rovers/nope` — один ETag `index.html`), `noindex` нет. Агент B ставил P1, A — P3; итог P2: пользователю не мешает, но поисковики и мониторинг ссылок видят «живые» битые адреса. Правка сервера — зона `backend-dev`, решение владельца.

**P3**

- Кнопка «Go to the rovers» — `btn-sm` 32 px, единственное действие экрана; иконка `--text-faint` блёклая.

## Насколько дизайн «свой»

Тексты знают предмет: солы у каждого марсохода свои, «Latest sol first» смешивает эпохи, у части снимков нет local time, «Each rover has its own scale». Пустые состояния подбирают причины по активным фильтрам. Композиция же — длинная форма-простыня (до 60+ чипов камер) над результатом; Stats — типовой дашборд «карточки KPI + столбики». Продукт узнаётся по словам, а не по устройству экрана.

## Что работает

- Search: пустые и ошибочные состояния образцовые — причины «от вероятной к маловероятной», отсчёт при 503, «Drop time-of-day and size filters» (`Search.tsx:584-653`); весь поиск в адресе; на телефоне фильтры свёрнуты в «Filters · 3 active».
- Stats: доступный график — `role=img` с итогом, чтение столбика через `aria-live`, ←/→/Home/End, табличный вид с теми же числами; вкладки — правильный `tablist`.
- `credit` на каждой плитке результатов; контраст в обеих темах без нарушений (кроме случая ниже); строка `API:` под результатами.

## Находки

### P1

1. **Search и Stats: ответ уходит за край экрана на 1280.** Search: форма 776 px, первая плитка на y≈1028, после «Search»/Enter прокрутки нет (`scrollIntoView` только при смене страницы, `Search.tsx:143-149`), статус «226 photos» тоже вне экрана. Stats: сводка на y=1124, график на y=1816. Общая причина — `CameraPicker` раскрыт по умолчанию (`useState(true)` в `Search.tsx:97`, `Stats.tsx:82`), хотя в макете `design/mockups/search.html:107` это свёрнутый `<details>`; на ≥760 px `.filters-toggle` скрыт, форму не свернуть.
   - AC: «1280×800, `/search`, отправлена форма → верх блока Results в первом экране, фокус на заголовке Results»; «1280×800, `/stats` → список камер свёрнут, сводка по марсоходам начинается в первом экране».
2. **Search: «Назад» со снимка возвращает на scrollY 0 под форму; страница снимка теряет контекст поиска** (крошки ведут на сол, Newer/Older ходят по солу). Предложение: сохранять прокрутку в `history.state`; на `/photos/:id` при `from=` из поиска — «← Back to search results».
   - AC: «`/search?…` → открыт снимок → Назад → та же позиция прокрутки (±50 px); на странице снимка ссылка “Back to search results” ведёт на исходный адрес поиска».
3. **Stats: «Search» в строке камеры теряет период и «Full frames».** На `?rovers=curiosity,perseverance&sol_min=300&sol_max=400&group_by=camera` строка CHEMCAM_RMI = 1 170 фото, ссылка ведёт на `/search?rovers=curiosity&camera=CHEMCAM_RMI` = 60 235 фото («тяжёлый» запрос без сола). `Stats.tsx:819-824` (`searchLink`), а карточки правильно используют `searchLinkFor` (`:499-521`). `design/NOTES.md:164` требует «с теми же фильтрами».
   - AC: «строка камеры при sol 300–400 → ссылка Search содержит `sol_min=300&sol_max=400` и тип кадра; число найденных фото совпадает с числом в строке».
4. **Stats «By camera» на 375: страница растягивается до 683 px.** Скрытый `<span class="visually-hidden">Link</span>` в `th` (`Stats.tsx:785-787`) с `position:absolute` (`styles-base.css:235-242`) не клипуется непозиционированным `.table-wrap` (`overflow-x:auto`). Измерено: `scrollWidth` 683 → 375 без этого span. WCAG 1.4.10.
   - AC: «375×812, `/stats?group_by=camera&rovers=curiosity,perseverance` → `documentElement.scrollWidth` = 375».

### P2

5. **Неверный текст ошибки диапазона (общий `api/errors.ts:62`).** API отвечает «sol_min must be less than or equal to sol_max», интерфейс пишет «From sol: must be a whole number from 0 to 2,147,483,647», поле не подсвечено. Достижимо ссылкой/закладкой. Затрагивает Search и Stats.
   - AC: «`/stats?rovers=curiosity&sol_min=500&sol_max=100` → текст “From sol must not be greater than To sol”, оба поля `aria-invalid`».
6. **Search: строка-резюме строится по черновику, а не по применённому поиску** (`Search.tsx:200`; то же `Stats.tsx:202`) — снял чип без отправки, резюме противоречит сетке.
   - AC: «снят чип без отправки → резюме над результатами не меняется, рядом пометка “изменено — нажмите Search”».
7. **Единственный выбранный марсоход выглядит выключенным** — `opacity:.45` (`stage19.css:172-173`) на `.chip[aria-pressed=true][aria-disabled=true]`, ≈2.5:1. Выбрать один марсоход — 4 клика (нет «Only»). WCAG 1.4.3/1.4.11.
   - AC: «`/search?rovers=curiosity` → чип Curiosity с полной непрозрачностью, контраст ≥ 4.5:1».
8. **Камеры с нулём фото выбираются** (у Curiosity `CHEMCAM`, `FHAZ`, `MAST`, `NAVCAM`, `RHAZ`; `MINITES` у Opportunity/Spirit) — прямой путь к пустому результату; камеры названы кодами, полное имя только в `title`.
   - AC: «список камер → камеры с 0 фото скрыты под “Show empty cameras” или неактивны с пояснением».
9. **Stats: малые графики нельзя сравнить** — у каждого марсохода своя ось X и ширина столбика (Curiosity 172 месяца по ≈6 px, Ingenuity 33 на всю ширину). `BarChart.tsx:56-58`, `Stats.tsx:643-680`. Предложение: общая ось времени при раздельных Y.
   - AC: «`/stats` → один и тот же год стоит на одной горизонтальной позиции во всех графиках».
10. **Stats: неполный последний период выглядит как спад** (Nov 2026 — 14 солов; 2012 начат в августе).
    - AC: «текущий/неполный период выделен штриховкой и подписан “partial” в строке чтения и таблице».
11. **Stats на 375: ось Y внутри прокручиваемого SVG уезжает за экран** (Curiosity: SVG 1086 px в окне 309, `scrollLeft` 777); значение читается только `onPointerMove`, подсказка «Point at a bar» на касании неверна. `BarChart.tsx:93-98`, `:121-163`.
    - AC: «375, график Curiosity → подписи оси Y видны при любой прокрутке; тап по столбику показывает его значение».
12. **Stats: пустое состояние** показывает пользователю сырой `total_photos: 0` и `groups: []` (`Stats.tsx:293-295`) и перечисляет все марсоходы вместо выбранных (`:289`); пустая вкладка — только заголовок (`:615-619`).
    - AC: «`/stats?rovers=curiosity&sol_min=99999` → в причинах только Curiosity, без полей JSON; есть Reset filters».
13. **Stats: нет `h2`** — порядок `h1 → h3 ×10` (`Stats.tsx:444`, `:669`). WCAG 1.3.1.

### P3

- Search: sr-текст «, Local mean solar time on Mars» попадает в `innerText` плитки с ведущей запятой; предупреждение «Only the first 10,000 photos…» уже на стартовой странице; стартовая выдача — калибровочные кадры ChemCam; лид без ссылки на браузер снимков.
- Search: ошибка поля на 375 оказывается у края экрана; перенос фокуса на первое невалидное поле проверить не удалось (rAF в скрытой панели).
- Stats: «scale 0–8,499+» при оси до 10k, у Ingenuity половина высоты пустая (`niceMax`); «6 photos on 1 sols» (`BarChart.tsx:67-69`); «sol 5,077» с запятой против «sol 5077» в остальном продукте.
- Stats: горизонтально прокручиваемые `.table-wrap` без `tabindex`/`role=region` (WCAG 2.1.1); кнопка сортировки 51×18 и ссылки «Search» 41×19; 29 ссылок с одинаковым видимым текстом «Search».
- Чипы, `btn-sm`, `Reset` — 32 px (ниже 44, выше 24).

# План по этапам

**Цель проекта:** открытая неофициальная замена архивированного Mars Rover Photos API. Старые клиенты переезжают сменой хоста (v1, `LEGACY-API.md`), новые получают более полный API v2. Фронтенд — после того как бэкенд и ручки готовы.

Каждый этап запускается командой `/stage <номер>`. Этап закрыт, когда выполнены все пункты «Готово, когда». Отметки `[x]` и журнал ведёт тимлид.

## Этап 7. Полная история Curiosity и Perseverance
- [ ] Backfill всех солов с паузами и возобновлением с места остановки
- [ ] Отчёт сверки: число снимков по солам против `total` источника; выборочно — против известных значений старого API
- [ ] Проверка производительности ключевых запросов на полном объёме (`EXPLAIN ANALYZE`), индексы при необходимости. Известные кандидаты из ревью этапов 4–5:
  - `/api/v2/rovers/{rover}/cameras` считает снимки `GROUP BY camera_id` по всем фото марсохода на каждый запрос — хранить счётчики камер при синхронизации, как `sol_summaries`;
  - `count(*)` в v2 с фильтрами `camera` или `sample_type` без `sol` — индексы под `sample_type` и `(rover_id, camera_id)`;
  - v1 без `page` отдаёт все снимки сола без LIMIT (так в оригинале) — проверить на самых больших солах;
  - лёгкий манифест (у Curiosity больше 5000 солов) — предложение дизайнера, решить вместе с фронтендом.

**Готово, когда:** вся история загружена, сверка без необъяснённых расхождений, `photos?sol=N` и манифест отвечают быстрее 200 мс на локальной машине.
